# 薪资面板：薪资水平和查薪资

[English](salary.md) | [中文](salary.zh.md)

岗位页“薪资与福利”下面有一个薪资面板，“薪资 · 这个岗位给多少钱”。它把手上所有来源放在一起回答“这个岗位给多少钱”，并写明
每个来源有多可信：

- **薪资水平**（一直开着，不用 AI）：这个岗位写明的薪资，在你采集到的同类岗位里排在什么位置，以及这家公司其他岗位写明的薪资。
- **查薪资**（默认关闭，用 AI 和网页搜索）：你点了才查，AI 在公开网页上搜这家公司的薪资水平和这个职位的薪资区间，并列出来源。

两者都在 `salary.yaml` 里设置（设置 → 薪资，或“高级”标签）。

## 怎么读这个面板

**顶部三格**

| 格子 | 内容 |
|---|---|
| JD 写明 | 岗位写明的薪资区间（事实），黄色高亮；下面写比同类岗位的中位高或低多少。只拿岗位自己的数字比较，AI 数字从不参与。待核对的薪资、或别的币种 / 地区的薪资不比较也不画：格子里写明这一点，或只写岗位原文。 |
| 同类岗位 | 基准组（见下）的中位数，以及这个岗位在组里的位置。 |
| 这家公司 · AI 估计 | 查薪资得到的本岗位区间，标“未核对”，下面写公司整体水平。没查过（或现在查不了）时，格子里写原因。查到了公司整体的数字却没有本岗位区间时，写“没查到本岗位区间”，公司整体中位标成“公司整体中位”，不会当成本岗位的数字。 |

**一把尺子放所有来源。** 格子下面四行画在同一条薪资刻度上（刻度按画出来的数字收拢，范围不超过 `ui.yaml` 的 `salary_axis`；超出刻度的值在
端点截断，并标 `«` 或 `»`）：

1. **本岗位**：JD 写明的区间（黄色块；上限低于你的薪资底线时是灰色）。
2. **同类岗位**：组的 P10 到 P90 画成色块，中位数画成虚线。
3. **同一公司其他岗位**：这家公司每个写明薪资的其他岗位一个点（相同的值合并成一个点并标次数，如 `×2`）。样本不少于
   `benchmark.min_sample` 才标中位数。
4. **这家公司 · 本岗位（AI）**：只画查薪资给出的本岗位区间，虚线框加斜纹，带 AI 的中位数。总包口径（含奖金或股权）的区间改用点状填充，并写明
   不能和基本工资直接比较。没有汇率的币种只按原币写出，不画。

每一行都写明数字的来源和可信度（“JD 原文 · 事实”“AI 网页搜索 · 未核对”）。没有数字的行也保留，写明缺什么。红线是你的薪资底线，也用文字写出来。

**底部。** 左边是 AI 数字的出处（站点、provider、时间、发送了什么），右边是查询按钮、当天额度，以及“自己去看”的薪资网站链接。页首的年薪卡有一个
“看全部来源”链接指到这里。年薪卡的中位数是本月所有写明薪资的岗位的中位数，面板里的是同类岗位的中位数，两组不同，数字可以不一样。

## 薪资水平：基准

每轮采集结束后，`pipeline` 步骤用库里的岗位重建基准：

1. 写明薪资的岗位换算成按年、按市场基准货币的数字（和页首年薪卡上的换算值一致）。只算最近 `benchmark.window_days`
   天内首次发现的岗位。
2. 按标题归入**岗位族**：`role_families` 里第一个匹配的族胜出（`LLM Engineer` → 机器学习 / AI 工程师）。不匹配任何族的
   标题不进基准。
3. 按 岗位族 × 资历 × 地点 分组；薪资数不少于 `benchmark.min_sample` 的组保留分位数（P10、P25、中位数、P75、P90）。

岗位页从最窄的组开始找：“同族、同资历、同城市”，再到“同国家”“任意资历”“只看岗位族”，并写明用的是哪个组、组里有多少个
薪资。有薪资的岗位显示位置（“P72：高于中位数”），没写薪资的岗位也能看到所在组的区间。只有几个岗位的组只是粗略参考，
样本数总会显示出来。

基准只用岗位写明的薪资。AI 查询永不计入基准和任何筛选，包括薪资底线。面板只显示“样本 n”，不再拆分 JD / 查询样本数。

`benchmark.enabled: true` 时，`pnpm salary:benchmark` 立即重建基准并打印出来（`--json` 输出原始分组）。基准关闭时不会重算。

### 薪资网站链接

`deep_links` 列出面板里“自己去看”链接到的搜索页，用岗位的公司、标题或城市填进去；默认是 Levels.fyi、Glassdoor 和 Kununu。链接在你的
浏览器里打开，Job Radar 从不抓取这些网站。这些网站会拦截自动化客户端，所以链接格式是人工核对的；网站改了 URL 时，在
`salary.yaml` 里改模板。

| 占位符 | 替换成 |
|---|---|
| `{company}` | 公司名 |
| `{company_slug}` | 公司名小写、单词用 `-` 连接 |
| `{title}` | 岗位标题 |
| `{city}` | 城市 |
| `{country}` | ISO 国家代码 |

## 查薪资（AI 加网页搜索）

用 `lookup.enabled: true` 打开（设置 → 薪资 →“开启查薪资”）。面板随后出现“查薪资”按钮，不点就不会查。

点了之后：

1. 网页端排一个 `salary_lookup` 请求，由 ai-worker（容器模式下是 runner）领取。
2. 发给 AI 的只有**公司名、岗位标题、城市、国家和资历**，从不发你的画像，也不发 JD。AI 搜索网页、读薪资页面，回答公司的
   薪资水平、这个职位的区间、这家公司的相关职位、可信度，以及每个数字的来源。
3. 存之前先检查答案格式和合理范围：每个数字都要有答案里给出的 https 来源链接；超出 `lookup.sanity_annual` 的数字丢掉；金额换算成基准货币
   （没有汇率的货币只按原币显示，超过 `lookup.unconvertible_max_annual` 的数字丢掉）；
   不在 `lookup.allowed_fetch_domains` 里的来源标成“不在薪资网站列表中”。这些检查不核对来源或数字，列表内的主机也一样。面板会写明丢掉了几条。
4. 结果保存 `lookup.ttl_days` 天，同公司、同岗位族、同资历、同地点的岗位直接显示，不再重新查。“重新查询”会强制再查。

ATS 看板的公司名被纠正时，缓存查询及其键会跟随改名后的公司，或一起迁到合并后的公司。来源、provider 和原来的到期时间
保留，改名本身不需要再查一次。

限制：

- `lookup.max_per_day`：每 24 小时最多查几次（每次请求都算，失败的也算；直接用缓存的不算）。用完后岗位页的按钮变灰，直到较早的查询满 24 小时。
- `lookup.timeout_seconds`：一次查询的总时长，所有 provider 和重试加在一起。
- `lookup.max_searches`：每次查询最多搜索几次。Anthropic API 严格执行；CLI 只是被要求遵守。
- `lookup.web_search_usd`：Anthropic API 每次网页搜索的费用，计入 AI 用量和每月 API 预算。
- `lookup.allowed_fetch_domains`：每一项必须是一个具体网站。`co.uk`、`com.au`、`github.io` 这类公共后缀会被拒绝，因为它们等于
  放行下面所有网站。列表为空时 Anthropic API 完全不搜索。

由哪个 AI 来查，是 `ai.yaml` 里的任务 `salary_lookup`（设置 → AI → 任务覆盖）。只会尝试能搜索网页的 provider：

| Provider | 怎么搜索 | 域名限制 |
|---|---|---|
| `claude-cli`（默认，第一个） | WebSearch 和 WebFetch 工具，只对 `allowed_fetch_domains` 里的域名预先放行；需要 `claude` 2.1.296 或更新 | 只能打开列出的主机上的页面；搜索本身不受限 |
| `anthropic`（默认，第二个） | API 的服务端网页搜索工具 | 只采用列出域名的搜索结果 |
| `codex-cli`（只有你自己加上才用） | Codex 自带的网页搜索 | 没有：设置页会提示 |

DeepSeek 和 MiMo 不能搜索网页，这个任务里会跳过。没有可用的、能搜网页的 provider 时，面板会说明并链接到 AI 设置。

其他 AI 任务仍然完全不带工具；见 [ai-providers.zh.md](ai-providers.zh.md) 和 [SECURITY.md](../SECURITY.md)。

### 怎么看结果

- **AI 查询**：徽标表示这是 AI 网页搜索的结果。
- **AI 估计（未核对）**：公司整体水平、这个职位的档位和每个相关职位的档位都带这个标记。Job Radar 没有核对这些数字和来源。
- **AI 自评置信度**：模型对自己答案的判断，不是 Job Radar 给出的置信度。
- **这家公司的薪资**：低于 / 接近 / 高于市场，或市场顶部，并给出典型薪资；这是 AI 的估计。
- **这个职位**：区间（类似 P10 到 P90 的范围和中位数，基本工资或总包），如果是基准货币的基本工资，还会显示它在你的基准组里
  的位置。
- **这家公司的相关职位**：AI 给出的其他区间。
- **AI 给出的来源（未核对）**：AI 提供的链接，带编号，每个数字都指向它们。“不在薪资网站列表中”表示主机不在
  `lookup.allowed_fetch_domains` 里。在列表中也不代表页面被打开过，或数字被核对过。

估计依据是公司、岗位类型、级别和地点，同类岗位共用这一次查询，不是根据这条 JD。在另一条岗位上发起的查询，面板会显示
“这次查询是在另一条岗位上发起的：”，附上那条岗位的标题和链接。那条岗位已删除时，显示“发起这次查询的岗位已删除。”

这些估计只用于显示，不是这个岗位的事实，也不计入薪资基准和任何筛选。依赖它们之前先看看来源。

关闭查薪资、或它的 AI 不可用之后，已存的结果仍然留在页面上；面板会写明为什么不能再查，并给出设置链接。

## salary.yaml 一览

```yaml
benchmark:
  enabled: true          # 每轮采集后重建
  window_days: 365       # 只算这个时间窗内首次发现的岗位
  min_sample: 5          # 更小的组不保留
role_families:           # 第一个匹配的胜出；正则，不区分大小写
  - id: ml_engineer
    label: { en: ML / AI engineer, zh: 机器学习 / AI 工程师 }
    patterns: ['\b(?:machine learning|ml|ai|llm)\s+(?:engineer|developer)\b']
deep_links:
  - { id: levels_fyi, label: Levels.fyi, url: 'https://www.levels.fyi/companies/{company_slug}/salaries' }
lookup:
  enabled: false
  ttl_days: 30
  max_per_day: 10
  timeout_seconds: 300
  max_searches: 8
  allowed_fetch_domains: [levels.fyi, glassdoor.com, glassdoor.de, kununu.com]
  sanity_annual: { min: 5000, max: 2000000 }
  unconvertible_max_annual: 100000000000
  web_search_usd: 0.01
```

旧设置 `benchmark.include_ai_lookups` 已由薪资配置迁移（1 → 2）删除；自动和手动升级方式见
[configuration.zh.md](configuration.zh.md#薪资salaryyaml)。

给岗位族的正则补上你所在市场语言的词（随产品发布的文件已经带了德语）。薪资网站链接的 URL 也能在设置页里改：它们只是你的
浏览器打开的链接，Job Radar 自己不会向它们发任何请求。必须是 `https://` 或 `http://` 开头的地址。

## 排查

| 面板上写着 | 怎么办 |
|---|---|
| “这个标题不属于任何岗位族” | 在 `role_families` 里给它加一条正则 |
| “写明薪资的同类岗位太少” | 每个组的薪资都不到 `min_sample` 个：等更多岗位，或调低 `min_sample` |
| “旧的薪资对比含 AI 数字，已隐藏；打开薪资基准后，下一轮会重新计算。” | 打开薪资基准（`benchmark.enabled: true`）后等下一轮，或打开后运行 `pnpm salary:benchmark`。基准关闭时运行命令也不会重算。 |
| “这个查询设置的 AI provider 都不能搜索网页” | 把 `claude-cli` 或 `anthropic` 放进 `tasks.salary_lookup.order`，并确认它可用（`pnpm ai:probe`） |
| 登录失效、限流、超时 | provider 自己的问题；请求不会自动重试 |
| “ai-worker 一直没有响应” | ai-worker 没在运行或正忙：看 `/sources` |
| “薪资相关的数据表还不存在” | 运行数据库迁移（`pnpm db:migrate`，部署时会自动做） |
