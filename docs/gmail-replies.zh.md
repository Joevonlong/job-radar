# Gmail 回信

Job Radar 可以从**你指定的一个 Gmail 标签**里读公司发来的申请回信，并在 `/pipeline` 上建议怎么改：面试邀请建议把卡片移到“面试中”，拒信建议移到“已拒绝”。**你按“确认”之前什么都不会变。**

默认关闭（`replies.yaml: enabled: false`）。关闭时不会打开邮箱。

## 做什么，不做什么

- 只读 `replies.yaml: label` 指定的标签（默认 `JobReplies`），不读整个收件箱。用 `EXAMINE` 只读打开标签，用 `BODY.PEEK` 读正文：不标已读、不移动、不打标签、不删除，也不发信。
- 判断靠本地规则（`replies.yaml` 里的正则）。**没有 AI 读这些邮件，邮件内容不离开你的机器。** Telegram 提醒里只有一个数字和看板链接。
- 每封信保存：发件域名（不存地址）、日期、主题、一句短引文、类别、匹配结果和你的决定。不存正文，不存附件。超过 `max_message_bytes` 的邮件不下载，只按邮件头判断。发件人是你自己 `GMAIL_USER` 的邮件会跳过。
- 已决定的回信过 `storage.decided_retention_days`（默认 90）天后清掉主题和引文；还在等待的保留。日志只有数量和类别。
- 只算看得见的文字：白色文字、零大小文字等 HTML 里隐藏的部分，在规则和引文之前就丢掉。如果信里有像是写给 AI 的指令，这一行会标出来。
- 用的是和 [gmail-alerts.zh.md](gmail-alerts.zh.md) 相同的应用专用密码。注意：谁拿到它就能打开整个邮箱，Google 不提供更小的权限，所以只放在 `.env` 里，不用了就撤销。

## 1. 建标签和过滤器

1. 在 Gmail 建标签 `JobReplies`。在“设置 -> 标签”里确认勾选了“在 IMAP 中显示”。
2. 运行 `pnpm replies:filter`。它根据 ATS 发件方和你当前的申请拼出一段 Gmail 搜索语句；只读数据库。
3. 贴进 Gmail 搜索框，选“创建过滤器”，勾“应用标签：JobReplies”和**“也应用于匹配的会话”**，否则已有的邮件不会进标签。也可以手动给邮件打标签；标签里 `lookback_days` 天内的邮件都会被读。

隔段时间再跑一次 `replies:filter`：新申请会带来新公司名。

## 2. 先试再开

```bash
pnpm replies:check             # 读标签，不保存，只打印数量和类别
pnpm replies:check --eml a.eml # 对一个本地文件分类；不需要邮箱和数据库
```

数量看着对，就把 `replies.yaml` 的 `enabled` 改成 `true`（Docker 用户改 `data/config/` 里的）。下一轮就会读标签。`pnpm replies:check --write` 立刻保存，功能关闭时会被拒绝。`pnpm run doctor` 的“Gmail 回信”一项显示状态。

## 3. 在 `/pipeline` 上决定

看板上方的条显示有几封回信在等，有回信等待的卡片显示 `✉ n`。展开这个条，每封信显示类别、看起来属于哪个申请、引文和建议：

- **确认**：执行建议：状态改变（时间线上留一条说明），或设置下一步。
- **忽略**：什么都不变。
- **类别**：纠正规则，建议会重新计算。规则判断不了的信是“未分类”，等你选。
- **申请**：把回信关联到别的申请，比如有几个都可能时。
- **撤销**：在“最近确认的”下保留 `panel.undo_days` 天。恢复状态（和进入该状态的时间）或原来的下一步；如果之后没有别的变动，事件也一起去掉。

如果你在确认前自己改了申请状态，以你的改动为准：这条建议作废，什么都不写。“已收到申请”这类不需要改动的信只记录，不询问。

## 建议什么

在 `replies.yaml: transitions` 里设置。已拒绝、已撤回、已归档的申请不会被改动。默认：

| 回信 | 申请当前状态 | 建议 |
|---|---|---|
| 面试邀请 | 准备中、已申请 | -> 面试中 |
| 面试邀请 | 面试中 | 下一步：约面试时间 |
| 拒信 | 已申请、面试中、Offer | -> 已拒绝 |
| 拒信 | 准备中 | 不改动；这一行提示关联可能不对 |
| Offer | 已申请、面试中 | -> Offer |
| 要求补材料 | 感兴趣、准备中、已申请、面试中、Offer | 下一步：发送材料，带截止日期 |
| 已收到申请 | 感兴趣、准备中 | -> 已申请 |

只有证据（会话、ATS 账号、公司、发件域名、职位名）达到 `match.min_score`，且明显高过下一个申请（`match.min_margin`）时才关联。否则等你决定，并列出候选。申请开始之前的邮件不会关联到它；还在“感兴趣”的申请只接受“已收到申请”。

## 排错

| 看到什么 | 意思 |
|---|---|
| 步骤 `replies` 失败：“the configured Gmail label does not exist (replies.yaml: label)” | 建标签或改名字，检查“在 IMAP 中显示” |
| 步骤 `replies` 跳过：`not_configured` | 没有设置 `GMAIL_USER` / `GMAIL_APP_PASSWORD` |
| 某封回信没出现 | 它不在标签里，或早于 `lookback_days` |
| 经常“未分类”或类别不对 | 在 `replies.yaml: categories` 里按语言加措辞；加一组就是加一种语言 |
