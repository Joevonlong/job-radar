After the setup wizard: tuning what you get

Start here: run docker compose up -d --build in the project directory and open http://127.0.0.1:3000; the setup wizard (/setup) asks for your language, market, profile, targets, sources, AI and Telegram and writes the files for you (see setup.md). This guide is for after the wizard: it explains the same settings page by page, so you can tune them later. Each step says which page to use, what to fill in, and how to confirm it took effect. The mock-ups use example values (a Berlin / Germany setup); yours will show your own market, cities and currency.

Web address: http://127.0.0.1:3000 on this machine; from a phone or another device, use your Tailscale address (public_base_url in data/config/notify.yaml). Changes made on the pages are written back to the YAML files in the project directory with comments preserved; editing the YAML directly works too, and the two are equivalent. (The project directory is the one that contains package.json, compose.yaml, config/ and data/.)

How it works

By default a cycle runs automatically on weekdays at 07:00 and 17:00 and at 09:00 on weekends, in your configured time zone (schedule.yaml). Each cycle goes through 6 stages, and each condition you set affects exactly one of them. Click a block to jump to the matching setup step.

Rank value = AI match score + signal bonus (capped). Jobs removed by the hard filter are not scored or notified, but they stay in the database and you can keep them manually at any time with "Keep anyway".

Where do I set the roles I want and my filters?

There are two kinds, and the first two cards are the easiest to mix up: "What to search" decides which jobs get pulled from the sites; "What I want" decides which of the pulled jobs stay and how they are scored.

My profile → What I want /me

Of the jobs pulled in, which stay and which are filtered out?
  • Target roles (also used for scoring)
  • Location, work mode, remote scope, seniority
  • Salary floor, contract type
  • Exclude student roles, companies, keywords

File data/profile/preferences.yaml → Step 3

Settings → Search /settings

Which keywords and cities to search on the sites?
  • Keyword groups (each group is OR-ed into one query)
  • Cities (each group is queried once per city), remote scope
  • Look-back hours per cycle, max results per group per city

File data/config/search.yaml → Step 4

My profile → About me /me

On what basis does the AI judge whether I fit?
  • Languages and levels, skills and years, years of experience
  • Home city, whether you need visa sponsorship, a summary for the AI

File data/profile/me.yaml → Step 2

Interests + notifications /interests /settings

Which jobs rank higher and get pushed to your phone?
  • Compensation / benefit signal words and bonus weights, watched companies
  • Notification threshold (default 70, 60 with a salary or equity signal), quiet hours
  • Saved filter views (switch at the top of the Today page)

→ Step 6, Step 7

⚠️ Keep both sides in sync. If you add a target role in /me but no matching keyword in the /settings search, the system will never go looking for it; conversely, if you add a search keyword but not the target role, the pulled jobs will get a lower title-match score. When you change one side, change the other.

/sourcespnpm run doctor
  1. Open http://127.0.0.1:3000 in a browser (on a phone, first connect with the Tailscale app, then open the Tailscale address). Left navigation: Today, Jobs, Favorites, Pipeline, Sources, Insights, Settings, My profile, Interests.

pnpm run doctor
All ✅ Everything is fine, go on to the next step.
Some ⚠️ It works, but something needs attention (for example a channel is missing its key). Each item has a "what to do" line below it.

Write pnpm run doctor, not just pnpm doctor (the latter is a built-in pnpm command). doctor is read-only: it sends no messages, calls no AI and costs nothing. The Sources page in the web UI shows the same information: each channel's status, usage and latest run, plus the heartbeats of the runner and ai-worker.

How the query count works

Queries per channel per cycle ≈ number of keyword groups × number of cities (plus one more for remote). 3 groups × 2 cities = 6 queries. More groups give better coverage, but paid channels cost more and free sites are more likely to rate-limit you.

When a save takes effect

On save, the settings are validated with the same rules as the runner; the runner hot-reloads within a few seconds, and "runner loaded" appears next to the button. The next collection uses the new criteria, with no restart needed.

While you are here, look at the "Schedule" tab: by default cycles run at 07:00 / 17:00 on weekdays and 09:00 on weekends, in the time zone you chose in the wizard (the shipped default is America/New_York); cycles missed while the host was off are made up after it boots.

How to confirm a channel works: click Test on the channel card in /sources. It runs only the first query, fetches at most 5 results and parses them in memory; it does not write to the database or count against the budget, and the result is shown right under the button. Paid and login-based channels have no Test button; use "Collect now".
Fill in keys yourself: open the .env file in the project directory with a text editor and fill them in; after saving, run docker compose up -d runner so the runner picks up the new values. .env is not in git, and never paste keys into a chat.

7Tune the ranking: signal bonuses, watched companies, views

/interestsdata/config/interests.yaml

💶 Signal words and weights

These phrases in a JD earn a bonus: T1 a stated amount, T2 equity / options, T3 salary description, T4 other. You can adjust each tier's weight and the bonus cap; after saving, rank values are recomputed immediately without calling the AI.

👀 Watched companies

Add companies you especially want to join. Any new job from them is pushed on its own, regardless of the score threshold and filters. You can add a company before it appears in the database.

👁️ Saved views

After setting filters in /jobs (score, city, remote, German requirement…), click "Save current filters as a view" and you can switch to it with one click at the top of the Today page; you can set one default view.

Every Monday at 08:00 the AI proposes adjustments based on your actions (marking interested / ignore). They appear on the /interests page and only take effect once you approve them.

8Run a cycle by hand and look at the results

/settings → Manual actions//jobs/<id>/pipeline
  1. In /settings → Manual actions click Run a cycle now (you can tick only a few channels). Live progress shows under the button: "Cycle N: x / y queries finished, z fetched". You can also run pnpm cycle:run in a terminal.
  2. After collection, the ai-worker starts scoring; scores usually trickle in within a few minutes.
  3. Open Today: new jobs are sorted by rank value, with per-source counts at the top.
  4. Click a title to open the detail page: the original JD / translation, the AI's match reasons and gaps, compensation signals, German requirement, and the "View original post" link (to record that you applied, click "Mark as applied"; opening the original post does not change the status).
  5. If you want to apply, click "Interested", then drag the status in the Pipeline board.

What to check when results look wrong

SymptomWhere to look first
A job you wanted did not appearIn /jobs turn on "Show filtered" and search for it: the top of the detail page states the filter reason (for example "location outside target area"). You can click "Keep anyway", or go back to Step 3 and loosen the conditions
Jobs of this kind were never fetchedWhether the Step 4 keyword groups contain that title; whether the Step 5 channels are healthy
Scores stay emptyWhether /me has skills or a summary; the "AI has no backlog" and "ai-worker heartbeat fresh" items in pnpm run doctor
Scores are all lowWhether the Step 2 summary and skills are specific enough; whether the Step 3 target roles cover the common titles
No notification on your phoneWhether it is quiet hours; whether the rank value reaches the threshold; send a Telegram test message from /settings

✓Every day after

  • Nothing to start: once the host is set up as in the deployment guide, Docker and the ai-worker start automatically at boot, and 3 cycles run on their own every day.
  • Watch Telegram: qualified new jobs arrive one by one; handle them with 👍 / 🚫 directly, and tap ⭐ to save ones for later.
  • When you have time, open Today or Jobs to browse what was not pushed; follow progress on the Pipeline board, which reminds you when a reply is overdue.
  • On Monday, check the AI's suggested adjustments on /interests and approve or reject them.
  • When something feels off, run pnpm run doctor; Telegram also sends proactive alerts (channel circuit-breaker, budget at 80%, ai-worker offline, etc.).
