# 日常使用手册

Job Radar 永不自动删除任何岗位、原帖、评分、翻译或分析。

第一次用先走设置向导（`/setup`，见 [setup.zh.md](setup.zh.md)）；向导之后想调整内容，看调优指南 [`getting-started.zh.html`](getting-started.zh.html)。

部署好以后，平时怎么用 Job Radar：怎么启动和打开、怎么知道它是否健康、在哪里看岗位和 JD。第一次部署、升级和回滚见 [`deploy.zh.md`](deploy.zh.md)，宿主机本身的设置见 [`host-setup.zh.md`](host-setup.zh.md)。

命令默认在项目目录（含 `package.json`、`compose.yaml`、`config/`、`data/` 的那个目录）下执行。

## 1. 启动和访问

### 它平时自己在跑

整套系统是 4 个 Docker 容器（`db` 数据库、`web` 网页、`runner` 定时采集、`jobspy` 抓取辅助），外加宿主机上的 `ai-worker`（macOS 上由 launchd 托管，Linux 上是 systemd 用户单元）（负责 AI 打分、翻译和 Telegram 推送）。它们都设置了自动重启：Docker Desktop 开机自启，容器就会自己回来，**平时不需要手动启动**。

处理轮按 `data/config/schedule.yaml` 自动运行（按其中的 `timezone`）：

| 轮次 | 时间 |
|---|---|
| 早轮 | 工作日 07:00 |
| 晚轮 | 工作日 17:00 |
| 周末轮 | 周六、周日 09:00 |

宿主机关机或睡眠错过了轮次，runner 启动时会补跑一次（`catch_up`）。只采一个通道的“立即采集”不算这个时段的轮次。定时轮次开始时如果有这样只采部分通道的一轮在跑，会等它结束再跑；如果在跑的是采全部通道的一轮，就跳过（见 [configuration.zh.md](configuration.zh.md) 的“轮次重叠”）。

### 手动启动和停止

| 要做的事 | 命令 |
|---|---|
| 启动（或代码改动后重建） | `pnpm stack:up`（= `docker compose up -d --build`） |
| 停止（数据保留） | `pnpm stack:down` |
| 只重启某个服务 | `docker compose restart runner`（或 `web` 等） |
| 看四个容器的状态 | `docker compose ps` |
| 正式升级到最新版本 | 运行 `scripts/ops/deploy.sh`（见 `deploy.zh.md`） |
| ai-worker 没在跑 | 运行 `scripts/ops/install-ai-worker.sh` |

永远不要运行 `docker compose down -v`：`-v` 会删除数据库卷。

### 打开网页

| 在哪里 | 地址 |
|---|---|
| 这台机器上 | http://127.0.0.1:3000 |
| 手机 / 其他设备（同一个 Tailscale 账号） | `data/config/notify.yaml` 里的 `public_base_url`（`https://<机器名>.<tailnet>.ts.net`） |

网页只在本机和 tailnet 里能打开，不在公网上。如果设了网页口令（见 [configuration.zh.md](configuration.zh.md#网页访问可选口令监听地址和端口)），其他设备会先出现一次登录页；会话保持 30 天，“退出登录”在侧栏底部（手机上在 ☰ 菜单里）。本机上的浏览器不需要口令。手机上先打开 Tailscale App 并连接，再打开这个地址。Telegram 消息里的链接也指向这个地址。

## 2. 监控：怎么知道它健康

### 一条命令全面体检：`pnpm run doctor`

```bash
pnpm run doctor
```

逐项检查容器、数据库、runner 和 ai-worker 心跳、claude / codex 登录、Telegram、Tailscale、备份、磁盘、各通道的 key 和预算、上一轮和下一轮、AI 积压，大约 40 项，每项是 ✅ / ⚠️ / ❌，⚠️ 和 ❌ 下面有「怎么办」。最后一行是汇总：

```
合计：39 ✅  3 ⚠️   0 ❌  —  有需要留意的地方（退出码 1）
```

- 全是 ✅（退出码 0）：一切正常。
- 有 ⚠️（退出码 1）：能运行，但有要留意的地方，比如某个通道缺 key、磁盘空间偏低。
- 有 ❌（退出码 2）：有东西坏了，按「怎么办」处理。

一定要写 `pnpm run doctor`，`pnpm run doctor` 是 pnpm 自带的另一个命令。doctor 是只读的：不发消息、不调用 AI、不花钱。每一项的含义见 `deploy.zh.md` 第 3 节。

### 网页上看：`/sources` 来源页

打开 http://127.0.0.1:3000/sources：每个通道一张紧凑卡片（指示灯、名称、本轮抓取的大数字、趋势、最近几轮的健康方块和一行状态；只有一轮记录时趋势写「1 轮」，从没跑过的通道写「无记录」）。点卡片底部的「详情」展开：立即采集 / 测试按钮、本月用量和预算、最近 10 次运行的条数和错误，LinkedIn 级联最近由哪个通道服务，AI 本月用量，runner 心跳，AI worker 卡片（心跳、队列、画像不完整时的提示）。今日页 `/` 顶部也有本轮各来源的条数和失败数。

### 不用看也会知道：Telegram 告警

出问题时 runner 会主动发 Telegram：通道熔断、LinkedIn 登录态失效或遇到验证页、预算到 80% / 100%、AI provider 全部失败、一轮没跑完、ai-worker 掉线、备份失败。同一类告警 24 小时内只发一次。每轮结束还有一条汇总消息（新岗位数、通过过滤数、合格数、失败的来源），**收到汇总就说明那一轮跑完了**。

### 只看一眼的快速检查

```bash
curl -s 127.0.0.1:3000/api/health          # 网页和数据库：{"status":"ok",...}
docker compose ps                          # 四个服务都应是 Up (healthy)
```

### 看日志

```bash
docker compose logs -f --tail 100 runner              # 采集、处理轮、推送排队
docker compose logs --tail 100 web                    # 网页
tail -f data/logs/ai-worker.out.log    # ai-worker：打分、翻译、推送
tail -f data/logs/ai-worker.err.log    # ai-worker 的错误
```

## 3. 看岗位：网页看板

主要入口是网页。各页面：

| 页面 | 用来 |
|---|---|
| `/` 今日 | 本轮和今天的新岗位，按排序值排；顶部是各来源的条数；可以切换保存的视图 |
| `/companies` 公司 | 按名称搜索公司，按在招岗位数、最高分或最近发现排序并翻页；关注或取消关注，也可跳转到画像的排除公司一栏 |
| `/favorites` 收藏 | 你用 ⭐ 收藏的所有岗位（含已关闭、被硬过滤、已忽略的，行里照常标出），默认按收藏时间排，也可以按排序值；每行可以写一句备注（最多 200 字，Enter 或离开输入框保存，Esc 取消）；取消收藏的提示上有「撤销」（备注和收藏时间一起恢复）。收藏和申请状态互不影响：一个岗位可以既是「已申请」又被收藏，收藏也不进看板、不触发"感兴趣超过 N 天"提醒。侧栏的数字是收藏总数 |
| `/jobs` 全部岗位 | 点"排序值""年薪""新鲜度"列头排序（再点切换升降序，见"列表排序"）；精准搜索 + 筛选（分数、薪资、高薪信号、来源、城市、国家、公司、办公方式、岗位状态、德语要求、合同、申请状态、日期（快捷范围或自定义，按发布日期或首次发现）；来源、城市、国家、公司、办公方式、合同、岗位状态、申请状态**可以多选**）；默认隐藏被硬过滤掉的岗位，可以切换显示（"只看被过滤的"即 `filteredOnly=true`，只列出它们：/insights 上被过滤的数字打开的就是它；不存进视图）；当前筛选可以保存成视图（「仅收藏」只看收藏的岗位，地址里是 `fav=true`，**不会**存进视图；「只看未看」是 `unseen=true`，同样不存进视图）；未看的岗位加粗带圆点，计数旁有「N 条未看 · 全部标为已看」（见"已看与未看"）；**当前 / 历史库（N）/ 全部**选择范围，历史库支持按原因筛选及最后列出排序（见"已关闭的岗位与历史库"）；打开幽灵岗位检查后，还有「幽灵岗位」筛选（全部 / 只看疑似 / 隐藏疑似）和分数下面的标记（见 [ghost-jobs.zh.md](ghost-jobs.zh.md)） |
| `/jobs/<id>` 岗位详情 | **JD 原文和译文（译成你设置的语言）**、AI 匹配理由和差距、薪酬与福利信号、德语要求、所有来源链接和"查看原帖"、"标为已申请"、申请状态、备注、"定制简历"；"标记为已关闭"（可写一句备注）/"重新打开"，已关闭的岗位会写明原因和原帖最近一次检查的时间 |
| `/pipeline` 申请看板 | 卡片的三个日期：申请日期是首次标为已申请的时间（不一定等于实际投递时间；缺少事件时显示「未记录」）；本状态自是进入当前状态的时间；下一步日期是计划的日历日。「新 / 感兴趣 / 准备中」没有申请记录时不显示申请日期。前两个日期按显示时区展示，撤销恢复原日期。工具栏可切换紧凑 / 舒适，两种密度字段相同，选择记在当前浏览器。Tab 导航会显示获得焦点的整张卡片；即使卡片其余部分在列的可视范围下方，点击可见标题也能打开详情抽屉。看板占满屏幕剩余高度，列头固定、卡片在各列内独立纵滚（已结束的三个分组共用一个滚动区）；桌面可用「上一列 / 下一列」按钮横向导航，手机照旧滑动；矮屏保持配置的看板下限，页头和筛选行在主内容区内滚走；落入已结束后自动展开并显示卡片。新 / 感兴趣 / 准备中 / 已申请 / 面试中 / Offer / 已结束；每列顶部的条是这一列占流程的比例；"流程中"只有一个定义：没有结束的申请（含「新」列），页面标题的"N 个岗位在流程中"、各列占比和侧栏"申请 N"数的是同一批；卡片上的进度条是在当前状态待了几天（阈值来自 `notify.yaml` 的 `reminders`，超过阈值的部分变红；读屏的刻度就是阈值本身，超出的天数写在读数里）；七列等宽，放不下时看板在自己的容器里横向滚动；「新」列显示有申请记录但还没决定的岗位（只写了备注、挂了简历，或被设回「新」的）；拖拽或用卡片右上角的「⋯ 移动到…」菜单改状态，改完的提示上有「撤销」（撤销会把这一步从时间线里去掉并恢复原来的计时，不会多记两条）；「已结束」列先显示被拒 / 我放弃 / 已忽略的数量，点开看卡片；键盘用户：Tab 到卡片上的拖动按钮，空格或回车拿起，方向键换列，空格或回车放下，Esc 取消（读屏会播报当前所在的列），也可以用「⋯ 移动到…」菜单 |
| `/sources/ai-usage` AI 用量 | 每次 AI 调用的模型、token、耗时、折合 API 费用和实际开支；时间范围、筛选、按天图、三张明细表、调用明细、导出 CSV（见 `ai-usage.zh.md`） |
| `/insights` 统计 | 每日新增、来源分布、城市、薪资披露率、信号分布、申请漏斗（7 / 30 / 90 天） |
| `/sources` 来源 | 见上一节 |
| `/me` 我的画像 | 编辑 `me.yaml` / `preferences.yaml`（简介和技能决定 AI 打分） |
| `/interests` 感兴趣清单 | 信号词、关注公司、AI 每周学习建议的批准 / 拒绝 |
| `/settings` 设置 | 所有配置的表单编辑；"手动操作"标签里有"立即跑一轮"、"重打过期分数" |

### 怎么看 JD

1. 打开 `/`（今天的）或 `/jobs`（全部的），点岗位标题进入详情页。
2. 详情页的 JD 区块是原文，可以切换到译文；还没翻译的点"翻译"，ai-worker 几十秒内完成（页面显示进度）。
3. 想投：点"查看原帖"打开原链接（公司 ATS 来源打开岗位页而不是申请表单，没有岗位页链接时才退回申请链接；聚合源用它挑好的雇主直链；只是打开，**不会**自动变成已申请）；确认投递之后再点"标为已申请"（有撤销）；或者点"定制简历"导出 JD 并拿到 resume-kit 命令（见 `resume-kit.zh.md`）。
4. 日期：详情页标题上方先写具体日期，相对时间放在括号里。黄色的 **发布 10/27 周二（4 天前）** 是 `posted_at`，即所有来源里最早的发布日期；`/jobs` 列表里的发布日期、发布日期筛选和 **排序：发布时间** 用的是同一个日期，所以一个岗位不会出现两个“发布”日期。所有来源都没给发布日期时显示 **发布日期未知**（日期筛选这时按首次发现日期算，按发布日期排序时排在最后）。下一项 *首次发现* 是我们自己的时间，按配置的时区精确到分钟，后面是来源；岗位在缺席后又被采集到时，再接一句 **再次出现**（见“已关闭的岗位和历史库”一节；这不等于重发）。鼠标悬停日期可以看完整时间、时区和日期靠不靠得住，读屏读到同样的文字。很多来源（例如 jobspy）只给日期、不给时间：这种日期按 UTC 的那一天显示，不写小时，也不按时区挪动（“来源只给了日期”），相对时间只按整天算。公司招聘页（Greenhouse、Lever、Ashby、Personio、SmartRecruiters）和用你自己登录的 LinkedIn 自己给出发布日期；聚合站的日期可能是刷新或抓取日期，仅供参考。[幽灵岗位检查](ghost-jobs.zh.md)发现同一来源把岗位换了新 id 再发时，发布 chip 旁会多一枚 **重发 · 新链接 10/27（我们首次看到，4 天前）**；来源自己标了重发但没有日期时显示 **重发（来源标注）**。这个日期是 Job Radar 首次看到新链接的那天，不是来源给的日期。它依赖已开启的幽灵岗位检查，`trusted_companies` 里的公司不显示。`/jobs` 列表在新鲜度条上方显示 `10/27 · 4 天`（手机上只有日期），没有发布日期时显示 `发现 10/27`；历史库仍显示它自己的“最后列出”。

快捷键：`⌘K`（Windows / Linux 上是 `Ctrl K`）打开跳转面板，查页面与岗位，列表里 `j` / `k` 上下移动，`s` 标为感兴趣（👍），`x` 忽略，`f` 收藏 / 取消收藏（★），`u` 把当前行在已看 / 未看之间切换，`c` 标记为已关闭（或重新打开）。详情页的「收藏」按钮（手机上是底栏里的星）同样可用。图标约定：★ / ⭐ 只表示收藏，👍 是"感兴趣"（申请流程里的一个状态），🏅 是 T3 "有竞争力"徽章（T1 到 T4 是四个薪酬信号类别：写明的金额、股权、定性的薪资措辞、奖金；见 [signals.zh.md](signals.zh.md)），📌 是视图的默认标记。

### 搜索岗位

**岗位**页的搜索框筛选列表。**跳转 ⌘K**（Windows / Linux 为 Ctrl K）打开页面或少量匹配岗位，末项可在岗位列表中查看全部结果。两个入口使用相同的默认匹配规则和相关度顺序。

默认搜索标题、公司名称与别名、城市、地点标签和国家，**不搜职位说明**。多个词之间为 AND，可以落在不同字段。拉丁短词只匹配整词（`AI` 不命中 `Maintenance` 或 `Airbus`），较长的词允许词首前缀匹配。`C++`、`C#`、`.NET` 保留符号。双引号要求同一字段内的连续短语：`"product manager"` 不命中 `Product Marketing Manager`，也不跨标题和职位说明拼接。匹配时统一大小写和全角字符。只有标点时提示“没有可搜索的词”，超出词数上限时提示只使用了前面的词。限额见 `job-search.yaml`（[配置说明](configuration.zh.md)）。

`Germany`、`Deutschland`、`德国` 等国家名同时匹配国家代码和字面文本。`DE` / `de` 等非歧义代码只匹配国家；加引号 `"de"` 才按字面词搜索。`AI`、`IT`、`US` 等歧义代码仍是普通文本。**国家**多选始终精确筛选已存的国家代码，不从职位说明推断。选项和岗位数跟随“当前 / 历史库 / 全部”范围；已选但该范围没有岗位的国家仍显示，计数为 0。公司下拉计数仍按未筛选列表计算。

**包含职位说明**会加入原文和完整且未过期的已有译文（URL 为 `searchIn=all`）。零结果时提供**也搜索职位说明**链接，点击前不额外查询全文计数。中文查询会显示语言提示：搜索不会自动翻译查询词，可以打开开关查已有译文。刷新和分享链接保留开关，清空筛选也保留它。全文搜索超时时会提示缩小查询范围，并提供只搜索基本信息的同一搜索链接。

有查询词时默认按**相关度**排序，优先标题短语和基本信息命中，再排只在职位说明里命中的岗位。相关度固定降序，隐藏方向按钮；可以显式选择其他排序，或点击计数旁的**改按排序值**。没有查询词时沿用当前范围的默认排序。

国家与搜索范围**不保存进视图**，保存框会说明；只有这两个条件时保存按钮禁用，并提供同一句提示。已存查询词按默认基本信息范围搜索。

### 多选筛选

`/jobs` 的来源、城市、国家、公司、办公方式、合同、岗位状态可以各选多个值（申请状态本来就能多选）：

- 点开筛选框，勾选想要的项；城市、来源、公司和国家有搜索框（输入 `munc` 能找到 München）；底部有"已选 N 项 · 清除 · 完成"。键盘：Tab 到按钮，Enter / ↓ 打开，↑ ↓ 移动，Enter 勾选，Esc 关闭。
- 规则：**同一项里满足任一即可，不同项之间必须同时满足**。比如"城市 Berlin + München，办公方式 远程"= 在 Berlin 或 München 的远程岗位。选 München 会连带它的都市圈写法（Garching 等）。
- 搜索框下面一行标签列出每个已选值，点 × 只去掉这一个值；手机上不打开筛选面板也能看和删。"筛选 (n)"里一个多选筛选只算 1。
- 地址里是重复参数：`/jobs?city=Berlin&city=M%C3%BCnchen&workplace=remote`。旧的单值链接（`?city=Berlin`）照常可用，读成"只选了一个"。空值、不认识的值、重复值会被忽略。
- 保存成视图时，选一个值写成单个值（`city: München`，和以前的文件一样），选多个写成列表（`city: [Berlin, München]`）；手写 `interests.yaml` 两种写法都可以。`/interests` 的视图卡片显示"城市：Berlin或München"；今日页切到这个视图按多个值筛，标签上的数字一致。今日页的视图标签本身仍是单选（视图是互斥的预设）。
- 回退提醒：如果回退到支持多选筛选之前的版本，旧代码不认列表写法；回退前先把多值视图改成单个值或删掉，再跑 `pnpm config:check`。

### 按公司筛选

`/jobs` 的"公司"筛选和城市一样是多选（选几家 = 任一家即可；和其他筛选之间必须同时满足）。地址是 `/jobs?company=SAP%20SE&company=Zalando%20SE`，保存成视图写成 `company: [SAP SE]`（总是列表）。

- 下拉里列出在 `/jobs` 默认列表里有岗位的公司（被硬过滤的、已关闭的岗位不算），按岗位数从多到少，名字旁边是数量。最多加载 `ui.yaml: filters.company_options_max` 家（500），不输入搜索词时只显示前 `filters.company_options_visible` 家（50），列表下方有提示。没加载进来的公司也能一步筛到：点它的名字。
- 在岗位行或岗位详情页点公司名，就列出这家公司的岗位（`/jobs?company=…`），不会打开这个岗位。
- 公司链接打开默认列表，不带"显示已过滤"或岗位状态筛选。这家公司的硬过滤或已关闭岗位不会出现在其中；加上相应筛选才能看到。
- 名字和公司的对应规则与硬过滤的排除公司相同：不分大小写、重音和法律形式（GmbH、SE 等），`pipeline.yaml` 的别名也算；不按名字的一部分匹配，选 "SAP" 不会带出 "SAP Fioneer"。链接里手写的名字（`?company=sap`）只对应一家公司时，会改写成这家公司的显示名。
- 视图保存后公司改了名或被合并，这个公司可能显示为"已选但没有岗位"；在下拉里重新选一次即可。
- 同一家公司存了两条记录时（后来加了别名，旧记录和新记录都在），这个名字会同时选中两条记录，所以点进去的列表可能比下拉里这一行旁边的数字多。

### 公司总览

只剩休眠岗位的公司不再显示，公司岗位数也不含休眠岗位；⌘K 搜索同样不返回它们。

从侧栏、手机菜单或命令面板打开**公司**（`/companies`）。这里只列出在 `/jobs` 默认列表里有岗位的公司：被硬过滤、已关闭或休眠的岗位不计入，未打分、可能已关闭和手动重新打开的岗位都沿用 `/jobs` 的规则。每行显示在招岗位数、当前最高排序值，以及最近一个岗位的首次发现时间（按配置的时区显示）。可以按公司名称搜索，点列头排序，再点一次切换升降序；手机上用卡片上方的下拉框和箭头按钮。没有分数的公司始终排在最后。每页数量由 `ui.yaml: companies.page_size` 控制，默认 50 家。

- 点公司名打开 `/jobs?company=…`。总览每行只统计一条公司记录；如果同一个名字或别名匹配多条记录，链接会打开它们的岗位合集，数量可能比这一行显示的更多。
- **关注**和**取消关注**立即更新关注列表，`/interests` 同步显示。取消时会删除所有匹配的原始名称，即使页面显示的是简称也能取消。如果数据库也有关注标记，成功提示会说明这家公司仍处于关注状态。**已关注（来自数据库标记）**表示关注名单没有对应条目；这种情况在这里不提供取消按钮。
- 如果别名配置变更后记录仍使用旧的公司 key，或名称超过关注列表的 120 字符上限，该行会提供前往 `/interests` 的链接。请在那里添加当前公司名或较短的别名。
- **排除…**打开 `/me#exclude-companies`，直接定位到画像的**排除公司**一栏。在那里添加公司并保存偏好。保存本身不会重跑过滤，下一轮处理会应用新偏好；也可以运行 `pnpm refilter` 提前更新已有岗位。岗位全部被过滤后，公司便不再出现在总览里。列表上方的排除数量是画像排除名单的条目数，包含没有可见岗位的公司，不包含仅在数据库里标记排除的公司。

### 远程岗和关注公司

除了你的目标城市，还有两条规则决定岗位可以在哪里。

**远程范围**（`/me`、`/settings` 和设置向导里的下拉；选择框下的说明随所选种类变化）。德国市场包的 `home_country` 显示为“能从德国远程（含面向欧盟 / 欧洲 / EMEA / 全球的远程岗）”：

| 远程岗 | 结果 |
|---|---|
| “Remote - Berlin”、“Munich (Remote)”（你的目标城市） | 保留：目标城市优先 |
| “Germany (Remote)” | 保留，注明地点只写到国家 |
| “Remote - EU”、“Europe”、“EMEA”、“EEA”、“Europa” | 保留：所在区域 |
| “Remote - Worldwide”、“Anywhere”、“Global”、“weltweit” | 保留 |
| “Remote - Spain”、“Remote, UK”、“Austria” | 排除：别的国家 |
| 同上，但正文写明可在欧洲任何地方或从德国受雇 | 保留，加注 |
| “Remote - USA”、“Americas”、“APAC”、“Austin, TX” | 排除（正文可以救回） |
| 标题带 “AI Engineer - US” 或 “(Americas)” 这类标记 | 排除，正文也救不回；标题同时写了 EMEA 或 Europe 则不排除 |
| 只写 “Remote”（没写地方）或没有地点 | 保留，注明没写在哪里招 |

`none` 不收远程岗（地点在你的目标城市的除外），`worldwide` 全部保留，`region` 保留你选的区域和国家（以及全球）。`/settings` 里的远程范围决定远程查询用什么地点去搜，过滤用的是“我的画像”里的同名设置。

**关注公司的现场岗和混合岗在本国任何城市都保留。** 对关注名单里的公司（`/interests`、`/companies` 的“关注”，或数据库标记），非远程岗只要至少一个地点在你的本国，就通过地点检查，不管是哪个城市，并注明“关注公司：Hamburg 不在目标城市，但在本国，按关注公司保留”。只放宽地点检查：

- 来源没有写明属于本国的地点不算：“San Francisco”“Bengaluru”，或城市表里没有、来源也没给国家的小城市，仍按“地点不在目标范围内”排除。大多数来源会给国家（Arbeitsagentur 总是给，LinkedIn 写“……, Germany”）。
- 远程岗仍按上面的远程范围判定。办公方式、合同、学生岗、薪资底线、资历、排除关键词和排除公司、一票否决，以及你自己的保留 / 排除决定都不变，打分和推送规则也不变。
- 每次过滤都重新读名单，所以添加或移除公司，下一轮就改变它的岗位。读不到 `interests.yaml` 时名单视为空（记一条警告），只有数据库标记生效。
- 公司只有在配了 ATS 看板（见下）或某个来源返回了它的岗位时，才会在所有城市被采到；否则只有按你的目标城市的查询能采到。`/interests` 会标出没有看板的关注公司。

### 按日期筛选

`/jobs` 筛选面板里的**日期**组有两行按钮：

- **按**：比哪种日期。**发布日期**（默认；`ui.yaml` 的 `filters.date_default_field` 可以改）是来源给出的发布日期，没有发布日期的岗位改用首次发现日期来比；岗位上显示的发布日期不会因此被补上。**首次发现**是本工具第一次采集到这个岗位的日期。
- **范围**：**不限**，然后是快捷范围（默认 **1 天内**、**7 天内**、**2 周内**、**本月**；清单是 `ui.yaml` 的 `filters.date_quick_ranges`，见 [configuration.zh.md](configuration.zh.md#日期筛选uiyaml)），最后是**自定义…**，展开“自”“至”两个日期框（按显示时区的整天算）。

需要知道：

- 按天的范围是滚动的：**1 天内**是最近 24 小时，不是“今天”。**本月**从显示时区（`schedule.yaml: timezone`，没配置就按 UTC）本月 1 日 0 点算起。起点每次打开页面时重新计算，所以存成书签的链接始终是“最近 7 天”。
- 快捷范围和自定义日期互斥：选了一个就清掉另一个。只限制起点；来源写错、发布日期晚于现在的岗位也算在范围内。
- 日期条件在搜索框下方是一个标签（`发布 · 7 天内 ×`、`首次发现 · 本月 ×`、`发布 · 10-01 – 10-15 ×`），点 × 整个清掉；在“筛选 (n)”里算 1 个。
- 列表、总数、未看数和“全部标为已看”总是用同一个日期条件。排序不变：**发布时间**按真实发布日期排，所以只是靠首次发现日期进到范围里的岗位排在最后。
- 来源换了新链接重新发布的岗位会合并进原来的岗位，保留最早的发布日期，所以不会出现在“7 天内”里。“再次出现”指消失后又回来，不是一回事。
- 个别来源可能会刷新发布日期，让老岗位在按发布日期筛选时看起来像新的。把**按**切到**首次发现**，就按本工具第一次看到它的时间来比。
- 链接写法：`/jobs?within=7d&dateBy=posted`。`within` 是 `Nd`（N 为 1 到 366 天）或 `month`；`dateBy` 是 `posted` 或 `seen`；`from` / `to`（`YYYY-MM-DD`）是自定义日期。链接里没有 `dateBy` 就按首次发现，所以旧链接、已保存视图里的日期和 MCP 的 `since` / `until` 含义不变。`within` 和 `from` / `to` 同时出现时以 `within` 为准。不合法的值会被忽略。
- 保存视图会保存日期条件。选了 **7 天内** 再保存，视图存的是范围而不是日期（`interests.yaml` 里的 `within: 7d`），所以下周打开它，看到的是下周的最近 7 天。自定义日期则原样保存这两个日期。按发布日期比较的视图还会存 `dateBy: posted`；没有 `dateBy` 的视图按首次发现比，这也是快捷范围出现之前保存的所有视图的含义。“今天”页和视图的趋势图不看视图里的日期：今天就是今天。回退到更早的版本：见 [带日期筛选的升级](upgrade.zh.md#带日期筛选的升级)。

### 列表排序

`/jobs` 宽屏列表的列头 **排序值**、**年薪**、**新鲜度** 可以点击排序（其他列不排序）：

- 点一个列头按它排序，高的 / 新的在前；再点同一个列头切换升降序。列头旁的箭头标出当前排序列和方向，其他可排序的列头显示淡色的双向箭头。键盘：Tab 到列头，回车。
- **年薪** 按市场基准货币的可比年薪排序（写明区间取中点，否则取写明的那一端；和详情页的中位数同一口径）。标为"可能是外地薪资"的排在所有可比年薪之后；没有可用薪资的岗位（未披露、待核对、还没按当前基准货币换算）不论升序降序都排在最后。按排序值排序时，没打分和被硬过滤的岗位也始终在最后。
- 手机上（以及窄窗口）没有列头：用筛选里的 **排序** 下拉（也有"年薪"、"发布时间"和"最后列出"），旁边的箭头按钮切换升降序。列头、下拉和按钮改的是同一个设置，任何宽度下顺序一致。
- 地址会记住排序：`/jobs?sort=salary&dir=asc`（默认的降序不写 `dir`）。旧链接如 `?sort=rank` 照常可用。保存的视图不存排序。今日页和收藏夹保持各自固定的顺序。

### 已看与未看

每个岗位都记得你看过没有，点开几条再返回列表就能分清：

- **未看**的行标题加粗，前面有一个小圆点；**已看**的行标题是正常字重。今日、`/jobs`、收藏夹三处一致（屏幕阅读器会读出"未看：……"）。
- 岗位在这些时候记为**已看**：详情页真正在浏览器里显示出来（只是悬停链接或页面被预取不算）；点「查看原帖」（包括手机底栏的按钮和"来源"面板里的链接）；在列表行上做了操作（★、👍、✕ 或标记关闭）。只保留第一次的时间。
- **只看未看**（`/jobs` 上「仅收藏」旁边）只列出未看的岗位，可以和其他筛选组合；它在地址里（`unseen=true`），不存进保存的视图。
- 结果计数旁的 **N 条未看 · 全部标为已看**：在 `/jobs` 作用于当前筛选下的**全部页**，在今日页作用于当前视图的列表。之后的 toast 带「撤销」，只撤回这一批（之前已看的保持已看）。
- 想让岗位重新变成未看：详情页「⋯」菜单里的「标为未看」，或在列表行上按 `u`（再按一次改回已看）。
- **上次访问后新增**：系统仍然记得你上次打开今日或 `/jobs` 的时间（一次访问是一个会话：间隔不到 30 分钟的打开算同一次）。`/jobs` 按新鲜度从新到旧排序时，在最后一条新岗位下面有一条分隔线"以上为上次访问后新增 · N 条"（只出现在分界所在的那一页）；其他排序下，计数旁显示"上次访问后新增 N 条 · 按新到旧查看"，点链接切到这种排序；今日页只显示这句话。
- 升级后：上次访问之前首次发现的岗位，以及所有申请过或收藏过的岗位，一开始就是已看；之后的新岗位是未看。如果从没记录过访问，全部记为已看。

### 已关闭的岗位与历史库

Job Radar 不会自动删除任何岗位、原帖、评分、翻译或分析；它们一直保留在本机。

`/jobs` 标题下的 **当前 / 历史库（N）/ 全部**选择岗位范围。当前就是原来的默认列表；历史库包含有效已关闭
（用户判断优先）和已休眠的岗位。未休眠的可能已关闭岗位，包括由关闭短语标记的，仍在当前。当前与历史库
互不重叠，在同一组筛选下合起来就是全部。历史库计数跟随搜索和其他筛选；**全部标为已看**覆盖所选范围的所有页。

范围选项是一组页面内视图筛选链接：用 Tab 或 Shift+Tab 依次聚焦，按 Enter 打开。当前范围会标记为当前选项。

点击范围后，地址总会写入 `scope=current`、`scope=archive` 或 `scope=all`；岗位状态筛选与所选范围取交集。
例如当前 + 已关闭为空，移除状态标签后仍在当前；**清空筛选**也保留范围。不带 `scope` 的旧链接
（包括 `?status=closed&status=possibly_closed`）和保存的视图保持原来的结果：有状态筛选时是全部，无状态时是当前，不重定向。

非当前范围显示**原因**多选：你标记的已关闭、来源已下架、数周未被列出（`reason=manual`、`reason=gone`、
`reason=dormant`，多选满足任一即可）。离开历史库时清除原因。当前地址里已有的原因仍生效，虽无选择控件，仍可移除标签。
范围和原因不存进视图；从历史库或全部保存时，弹窗会说明。

历史库默认按**最后列出**从新到旧排序（同一时间按岗位 id），显式选择的其他排序优先；回到当前时清除显式的
最后列出排序及方向。最后列出指所有来源原帖中最新的采集时间，链接检查不算。在任何范围中，归档行都显示最后列出的
相对时间，悬停看首次发现日期；详情也显示来源日期。没有来源日期时显示**最后列出：未记录**。新鲜度条看首次发现；日期筛选默认按发布日期，没有发布日期时用首次发现，可以切换（见“按日期筛选”）。

**再次出现 · {相对时间}**标注在 `job-archive.yaml: relist.badge_days`（默认 14 天）内再次采集到的岗位，
与当前状态无关。悬停显示首次发现日期、再次出现次数，以及含义：**本工具再次采集到，不等于雇主重新发布**。
手动关闭的岗位仍关闭，关闭短语标记也保留。标签过期后，详情页仍保留再次出现的日期。

**再次出现**快捷筛选（`relisted=true`）在所选范围内使用同一个标签窗口，计数与列表一致，刷新后保留，
**清空筛选**会移除它。和范围、原因一样，它不存进保存的视图。
Today 在今天或最近一轮窗口内有有效 active、未忽略的再次出现岗位时显示**N 个岗位再次出现**链接，计数还与标签窗口取交集。
链接打开当前范围并开启再次出现筛选，带上 Today 当时的“包含被过滤”“隐藏语言要求”“高价值”开关，打开的列表可以比提示多。
再次出现不会刷新首次发现、发布日期或新鲜度，不会加入 Today 新岗位列表、KPI、上次访问后新增、导航徽标或 Insights，
也不会增加 AI 处理或 Telegram 推送。

**数周未被列出**是休眠岗位的黄色提示，状态仍是 `possibly_closed`。可能已关闭满 30 天后
（`pipeline.yaml: lifecycle.dormant_after_days`），它会退出默认岗位列表、公司总览、⌘K 搜索和自动处理。
通常是连续未被列出 7 + 30 天；因来源采集不完整而推迟进入可能关闭的岗位，从真正进入时起再等满 30 天。
在**历史库（N）**或旧链接的**可能已关闭**状态筛选中仍能查看；详情显示最后被列出的日期、**仍在招**和**确认已关闭**。
来源重新列出或选择“仍在招”会唤醒它。休眠后不再参加普通链接检查。收藏、有过用户在招/关闭判断、申请状态从
`new` 到 `offer` 的岗位不会休眠；被拒、放弃、已忽略的申请和硬过滤保留/排除覆盖不提供保护。不删除数据。
已保存的关闭短语引用始终显示在详情页的证据行里，岗位休眠后也保留显示。
显式状态视图仍显示旧分数和其他结果，醒来后由下一次过滤和信号步骤补齐当前偏好的结果。
岗位导航徽标也排除休眠和有效已关闭岗位，今日徽标排除今天关闭的岗位，所以升级后列表、公司数和徽标可能变小。

岗位关闭有两种来路：系统发现，或者你告诉它。

- **你来标记**：详情页的"标记为已关闭"（可写一句备注，最多 200 字，之后显示在页面上）、列表行的第 4 个按钮（⊘），或在行上按 `c`。提示里有"撤销"，恢复成操作前的样子。标记关闭同时记为已看。"重新打开"（同一个按钮 / 按键）让它回来。你的判断一直有效，直到你改它；即使来源又列出了这个岗位也不变（详情页会提示"来源在某日仍列出此岗位"，方便你重新打开）。
- **系统发现**：连续 `possibly_closed_after_days`（7）天没有任何来源返回、而它的每个通道在这之后都有过成功运行的岗位标为**可能已关闭**（黄色标签）。这是按时间给出的提示，不是定论：搜索只返回时间窗口内的岗位，某个查询没出现它说明不了什么。由链接检查来判定：任何一个链接仍在线就重新打开该岗位（页面自己写明不再接收申请而被标记的除外），只有检查到的所有链接都返回 404 / 410 才关闭；任何来源再次看到它，它就恢复为有效（页面写明不再接收申请、或你手动关闭的除外）（见[数据源](sources.zh.md#岗位怎样被标为可能已关闭)）。连续 `unseen_link_check_after_days` 天（14）没有任何来源返回的有效岗位，也会直接检查链接，不依赖通道运行记录，两次至少间隔 `unseen_link_check_interval_days` 天（7）；不会先打黄色标签，检查无法给出答案时保持有效。这个兜底使用普通链接检查（先 HEAD，必要时再 GET，带自己的 User-Agent），不读取 robots.txt，也会检查复查未能给出答案的关注岗位，包括被 robots.txt 禁止访问页面的情况。你**收藏**的、或申请状态为**感兴趣 / 准备中 / 已申请 / 面试中 / Offer** 的岗位，另外每 72 小时复查一次原帖页面（每轮最多 10 个）：404 / 410 →**来源已下架**；页面可见文字里出现"no longer accepting applications"、"Stelle ist bereits besetzt"这类句子 →**来源写明不再接收**，这只把岗位标为可能已关闭，并保存命中的句子和一小段原文作为证据（鼠标悬停标签可见，详情页标题下也会写出，并带被检查页面的链接）。你可以点"确认已关闭"，或者点"仍在招"（这个判断会保留，之后的检查不再把它藏起来）。
- **已关闭的岗位去哪了**：`/jobs` 的历史库保留已关闭和休眠岗位，未休眠的可能已关闭岗位仍在当前。今日页保持原有范围；收藏夹照旧列出全部岗位，带标签。你关闭的岗位不再打分，也不推送到 Telegram。
- **复查怎么做**：每个岗位读一个页面，像一个守规矩的读者：自己的 User-Agent（`JobRadar/2 …`）、遵守 robots.txt（被禁止的页面不请求，记为"未查"）、同一网站每 3 秒最多一次请求、最多读 1 MiB、只搜可见文字（脚本、隐藏元素、导航、"其他岗位"这类侧栏和页脚都不算；最多前 200,000 个字符）。只请求公网地址：指向本机、Docker 网络或局域网的链接或跳转不跟随，跳转最多 5 次，跳到别的网站前先看那个网站的 robots.txt。页面正常打开时，可能已关闭的岗位重新变为在招。如果复查和兜底都得不到答案，比如页面要求登录或拒绝机器人，请在需要时手动标为关闭。短语来自市场包（`rules.yaml` 的 `closed_posting.phrases`，见 `market-packs.zh.md`）；可以在 `ui.yaml` 的 `job_checks.closed_recheck.extra_phrases` 里加自己的，或用 `enabled: false` 关掉复查。频率和大小在 `pipeline.yaml` 的 `lifecycle.watch_recheck`（见 `configuration.zh.md`）。
- 回退：旧版本会忽略你的关闭 / 仍在招判断和保存的证据，但不认识 `ui.yaml` 里的 `job_checks` 段：回退前先删掉它。

### 分数为什么是空的

排序值来自 AI 打分。岗位刚抓到时还没打分，按发布时间排在后面。打分在每轮结束后由 ai-worker 完成。如果一直没有分数：

- `pnpm run doctor` 看「画像够 AI 打分用」和「AI 没有积压」两项；
- `/me` 至少要填简介或技能，否则打分会暂停（今日页顶部会有横幅）；
- 详情页可以点"立即打分"单独打一个。

### 手机上：Telegram

每轮结束后，合格的新岗位（排序值 ≥ 70，带高价值信号的 ≥ 60（默认是达到薪资底线的写明金额或股权）；关注公司的不受门槛限制）逐条推到 Telegram，每条有 👍 感兴趣 / 🚫 忽略 / 📄 定制简历 三个按钮（点了直接写进申请记录）和一个 ⭐ 收藏 按钮（只加星标，不改申请状态，按钮保留，再点取消）。每轮最多推 10 条，其余在网页看。22:00–07:00 静默。规则见 `telegram.zh.md`。

## 4. 命令行

### 立即跑一轮（不等定时）

```bash
pnpm cycle:run                                  # 跑一轮完整的采集 → 处理 → AI → 推送
pnpm cycle:run --channel arbeitsagentur         # 只跑一个通道
pnpm cycle:run --channel <id> --dry-run         # 只在内存里采集、解析，不写库
pnpm cycle:run --backfill 2d --channel linkedin-guest  # 将手动补抓加入队列，交由 runner 执行
```

`--backfill <N>h|<N>d` 接受整数小时或天数（1–720 小时，还受 `collect.max_backfill_hours` 限制）。
它只将请求加入队列，要求 `--kind manual`（默认值），且不能与 `--dry-run` 同用。
可在 `/sources` 或 `/settings` 的请求队列中查看；见[手动补抓](sources.zh.md#手动补抓)。

要完整跑一轮，也可以在 `/settings` 的"手动操作"标签点"立即跑一轮"。

试跑会发出真实请求，付费通道照样计费，但不写数据库。数据库可达、已迁移且可读时，会通过只读连接读取已存的本月用量、熔断状态和岗位，按真实运行的规则判断能否请求：额度用完就停，除非配置了超额单价且美元预算还有余量；熔断仍在冷却中的通道也会跳过。没有通道可用时，日志 `cascade has no available channel` 会说明原因。这不是严格的账单上限。

已存岗位按各通道的规则复用：Arbeitsagentur、StepStone、XING 看 `reuse_known_details`；JSearch 只用已存描述兜底，不减少详情请求；LinkedIn session 不再打开本通道 id 下已存岗位的页面。试跑用量不计入当月累计，连续试跑每次都能用到同一份剩余额度。Brave 没有月预算检查。数据库连不上、没迁移或读不了时，CLI 会警告并从空状态开始，付费通道也就无法依据已存的本月用量限制请求。LinkedIn session 的每日页面上限和登录标记限制见[会话通道说明](linkedin-session.zh.md#真实冒烟)。

### 在终端里看岗位和 JD

日常还是网页最方便；想在终端里快速看，可以直接查数据库（只读）。下面的命令会用容器里的数据库账号，不需要你输入密码。

今天排名最前的 20 个岗位（通过了硬过滤的）：

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
select j.id, s.rank_value::int as rank, left(j.title, 50) as title, left(c.name, 24) as company,
       j.workplace, to_char(j.first_seen_at at time zone 'UTC', 'MM-DD HH24:MI') as seen
from jobs j
join companies c on c.id = j.company_id
left join lateral (select * from scores where job_id = j.id order by created_at desc, id desc limit 1) s on true
where j.status = 'active' and s.filter_result = 'passed'
order by s.rank_value desc nulls last, j.first_seen_at desc
limit 20;
SQL
```

看某一个岗位的完整 JD（把 `123` 换成上面的 id，或详情页地址 `/jobs/123` 里的数字）：

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -x -v id=123' <<'SQL'
select j.id, j.title, c.name as company, j.locations_json, j.workplace, j.contract,
       j.german_level_required, j.salary_json, j.description
from jobs j join companies c on c.id = j.company_id
where j.id = :id;
SQL
```

按关键词搜标题和描述（把 `kubernetes` 换成你的词）：

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v q=kubernetes' <<'SQL'
select j.id, left(j.title, 60) as title, left(c.name, 24) as company
from jobs j join companies c on c.id = j.company_id
where j.search_tsv @@ plainto_tsquery('simple', :'q')
order by j.first_seen_at desc limit 20;
SQL
```

想把一个 JD 存成文件：详情页点"定制简历"会导出到 `data/exports/jd/<公司>-<职位>-<日期>.md`（带 front matter），也可以在 Telegram 点 📄。

### 其他常用命令

| 命令 | 用途 |
|---|---|
| `pnpm run doctor` | 全面体检 |
| `pnpm config:check` | 改完 `data/config/*.yaml` 或画像后检查格式（含 `ai.yaml` ↔ `models.yaml` 的跨文件检查） |
| `pnpm ai:probe --provider <服务商> --model <模型 id>` | 新模型加进 `data/config/models.yaml` 后，先用它发一次极小请求再去设置页选（`--model` 必须配且只配一个 `--provider`；不带 `--model` 时看各 provider 此刻是否可用） |

| `pnpm telegram:test` | 发一条测试消息，确认 Telegram 通 |
| `pnpm reprocess` | 规则改了以后，按新规则重新解析已入库的岗位（`--split-merged`：拆开旧版本因非拉丁文字名字而合并的岗位，见 [extraction.zh.md](extraction.zh.md#公司和标题的匹配键)） |
| `pnpm db:studio` | 打开 Drizzle Studio，在浏览器里翻数据库表 |
| `scripts/ops/backup.sh` / `scripts/ops/restore.sh` | 手动备份和恢复（见 `backup-restore.zh.md`） |

## 5. 每天的使用习惯（建议）

1. 早上 07:00 以后看 Telegram 的汇总和推送，对要跟进的点 👍，想先存着的点 ⭐ 收藏（之后在 `/favorites` 看）。
2. 有空时打开 `/`，过一遍今天的新岗位；值得投的进详情页看 JD 和匹配理由。
3. 投递后在详情页或 `/pipeline` 改状态，系统会按天数提醒你跟进。
4. 一周跑一次 `pnpm run doctor`，或者收到告警时再看。
