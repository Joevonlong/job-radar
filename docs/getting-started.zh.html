设置向导之后：调整你收到的内容

先从这里开始：在项目目录运行 docker compose up -d --build，打开 http://127.0.0.1:3000；设置向导（/setup）会问你语言、市场、画像、目标、来源、AI 和 Telegram，并替你写好文件（见 setup.zh.md）。这份指南用在向导之后：按页面讲同样的设置，方便你以后调整。每一步都写了在哪个页面、填什么、怎么确认生效。示意图用的是示例值（柏林 / 德国的设置）；你自己的会显示你的市场、城市和货币。

网页地址：本机 http://127.0.0.1:3000，手机 / 其他设备用 Tailscale 地址（data/config/notify.yaml 的 public_base_url）。页面上的改动都会写回项目目录下的 YAML 文件，注释保留；直接改 YAML 也可以，两种方式等价。（项目目录 = 含 package.json、compose.yaml、config/、data/ 的那个目录。）

职位需求和筛选条件在哪里设？

分成两类，最容易搞混的是前两张卡片：「搜什么」决定去网站上抓哪些岗位；「要什么」决定抓回来以后哪些留下、怎么打分。

我的画像 → 我要什么 /me

抓回来的岗位，哪些留下、哪些过滤？
  • 目标职位（也用于打分）
  • 地点、工作方式、Remote 范围、资历
  • 年薪底线、合同类型
  • 排除学生岗、排除公司、排除关键词

文件 data/profile/preferences.yaml → 第 3 步

设置 → 搜索 /settings

去网站上用什么关键词、在哪些城市搜？
  • 关键词组（每组 OR 合并成一次查询）
  • 城市（每组按城市各查一次）、远程范围
  • 每轮回看多少小时、每组每城市最多几条

文件 data/config/search.yaml → 第 4 步

我的画像 → 关于我 /me

AI 凭什么判断我合不合适？
  • 语言和等级、技能和年限、工作年限
  • 所在城市、是否需要签证担保、给 AI 的简介

文件 data/profile/me.yaml → 第 2 步

感兴趣清单 + 推送 /interests /settings

什么样的岗位排更前、推到手机？
  • 薪酬 / 福利信号词和加分权重、关注公司
  • 推送门槛（默认 70，带薪资或股权信号 60）、静默时段
  • 保存的筛选视图（今日页顶部切换）

→ 第 6 步、第 7 步

⚠️ 两边要对得上。只在 /me 加了一个目标职位、没在 /settings 搜索里加对应关键词，系统根本不会去搜它；反过来，只加了搜索关键词、没写进目标职位，抓回来的岗位职位名匹配分会偏低。改一边时顺手改另一边。

1打开网页，确认系统健康

/sourcespnpm run doctor
  1. 浏览器打开 http://127.0.0.1:3000（手机先打开 Tailscale App 连上，再打开 Tailscale 地址）。左侧导航：今日、岗位、收藏、申请、来源、统计、设置、我的画像、感兴趣清单。
  2. 在项目目录下跑一次体检，看最后一行汇总：
cd <你的项目目录>
pnpm run doctor
全是 ✅ 一切正常，继续下一步。
有 ⚠️ 能用，但有要留意的（例如某通道缺 key）。每项下面有"怎么办"。
有 ❌ 有东西坏了，先按"怎么办"处理再往下。

注意要写 pnpm run doctor，不要只写 pnpm doctor（后者是 pnpm 自带的命令）。doctor 只读，不发消息、不调用 AI、不花钱。网页上的 来源 页能看到同样的信息：每个通道的状态、用量、最近运行，以及 runner 和 ai-worker 的心跳。

每一项怎么起作用

#条件不符合时建议
1目标职位不过滤，只影响分数把同义的叫法都列上（AI Engineer / Applied AI Engineer…）
2–4地点、工作方式、Remote 范围过滤，原因如"地点不在目标范围内"只想看远程就去掉"现场""混合"；完全不看远程选"不接受"
5资历过滤，原因"级别不符"不确定就留"不限"，交给 AI 判断

新抓的岗位立刻按新条件过滤。想让库里已有的岗位也按新条件重新过滤：在项目目录下运行 pnpm refilter --dry-run 先看前后对比，确认后去掉 --dry-run 再跑一次（不抓取、不调用 AI）。

查询次数怎么算

每个通道每轮的查询数 ≈ 关键词组数 × 城市数（远程再加一次）。3 组 × 2 城 = 6 次。组越多越全，但付费通道花得越多、免费网站越容易限流。

保存后什么时候生效

保存时用和 runner 相同的规则校验；runner 几秒内热加载，按钮旁显示"runner 已加载"。下一轮采集用新条件，不需要重启。

顺便看一眼「处理时间」标签：默认工作日 07:00 / 17:00、周末 09:00，按你在向导里选的时区（出厂默认是 America/New_York），宿主机关机错过的轮次开机后会补跑。

7调排序：信号加分、关注公司、视图

💶 信号词表和权重

添加你特别想去的公司。它们一有新岗位就单独推送，不受分数门槛和过滤限制。还没出现在库里的公司也可以先加。

👁️ 保存的视图

在 /jobs 设好筛选（分数、城市、远程、德语要求…）后点"保存当前筛选为视图"，今日页顶部就能一键切换；可设一个默认视图。

结果不对时怎么查

现象先看哪里
某个想要的岗位没出现/jobs 打开"显示已过滤"，搜它：详情页顶部写着过滤原因（例如"地点不在目标范围内"）。可以点"仍然保留"，或回到第 3 步放宽条件
压根没抓到这类岗位第 4 步的关键词组里有没有这个叫法；第 5 步通道是否正常
分数一直是空的/me 有没有填技能或简介；pnpm run doctor 的「AI 没有积压」「ai-worker 心跳新鲜」两项
分数都偏低第 2 步的简介和技能写得够不够具体；第 3 步目标职位是否覆盖常见叫法
手机没收到推送是否在静默时段；排序值是否够门槛；/settings 发一条 Telegram 测试消息

✓之后每天

  • 什么都不用启动：按部署指南配置好主机之后，Docker 和 ai-worker 会开机自动运行，每天 3 轮自动跑。
  • 看 Telegram：合格的新岗位逐条推来，👍 / 🚫 直接处理；想先存着的点 ⭐ 收藏。
  • 有空打开 今日 或 岗位 浏览没推送的；申请 看板跟进进度，超时没回复会提醒。
  • 周一看看 /interests 里的 AI 调整建议，批准或拒绝。
  • 觉得不对劲时跑 pnpm run doctor；出问题 Telegram 也会主动告警（通道熔断、预算到 80%、ai-worker 掉线等）。
