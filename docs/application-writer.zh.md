# 申请写作助手

[English](application-writer.md) | 中文

投递表单常问“你为什么想加入我们？”这类问题，很多还要动机信。申请写作助手围绕一条规则：每一句关于你的话，都应该有你自己写下的依据。
这些依据就是 `/me` 上的**经历素材库**。

## 经历素材库（`stories.yaml`）

`/me` 上的**经历素材**卡保存你的项目和成果，一条一个：

| 字段 | 写什么 |
|---|---|
| 标题 | 简短的名字（“把计费迁到新平台”） |
| 做了什么 | 你负责的部分，用你自己的话写 |
| 结果 | 结果如何（可选） |
| 数字 | 每条一个，按你会怎么说来写（“月结从 5 天缩短到 3 天”） |
| 相关技能 | 这条经历体现的技术和技能 |
| 时间 | 自由填写（“2021–2023”） |
| 语言 | 你写这条用的语言代码（`en`、`de`、`zh` …），可选 |
| 标签 | 你自己的标签，可选 |

- **添加、编辑、删除、排序**都在卡片上完成，然后点**保存**：和 `/me` 上其他表单一样，保存之前不写文件，**重置**回到已保存的版本。
- **id。** 新素材第一次保存时按标题生成 id（`moved-billing-to-the-new-platform`；标题里没有拉丁字母时是 `story`、`story-2` …）。
  之后 id 不再改变，改标题也不变；回答会按 id 引用素材。
- **历史和回滚。** 每次保存都留一个快照；`/me` 的**历史**面板有**经历素材**一栏，能看每个版本的改动并**回滚**。素材库不参与打分：
  保存或回滚都不会让分数过期，也不会触发重新打分。
- **别处改过。** 打开 `/me` 之后文件被改过（另一个标签页，或手改），保存会被拒绝，卡片重新载入已保存的版本。
- **文件写坏。** `data/profile/stories.yaml` 有语法或格式错误时，卡片换成错误提示，指出哪一行（`pnpm config:check` 也会显示）。
  可以在历史里回滚，或手动修好文件。
- **联系方式。** 写作功能打开后，素材是要发给 AI 服务商的。素材里像是有邮箱地址或电话号码时，卡片会在保存前提示（不阻止保存）。
  不要写姓名、联系方式和证件号。

文件是 `data/profile/stories.yaml`（模板：`config/profile.example/stories.yaml`），所以它和 `data/profile/` 里的其他文件一起进每日配置归档
（[backup-restore.zh.md](backup-restore.zh.md)）。

### 从你写过的内容里提取素材

素材库下面的**从你写过的内容里提取素材**卡片让 AI 起草素材，来源有三种：

- **从我的画像提取**：`me.yaml` 的摘要和技能，别的都不发。
- **粘贴自述**：你粘贴的任何文字。
- **上传简历**：PDF、Markdown 或纯文本文件（`import.formats`），不超过 `import.max_file_bytes`。PDF 要有文字层：扫描件没有，会提示“没有可提取的文字”，请改为粘贴文字。文件只在内存里读取，不保存，也不写临时目录。

超过 `import.max_chars` 的文字会被截断，卡片会说明。这些按钮要求申请写作已打开，你按下之前什么都不发送；卡片上写明 `story_extract` 任务的提供方（`ai.yaml`）。AI 被要求去掉姓名、联系方式和证件号，但可能漏掉：草稿里疑似有邮箱或电话时会标出，和素材一样。文字还会留在哪里，见[提取素材](privacy.zh.md#提取素材)。

结果进入**待审核草稿**。采用之前 `stories.yaml` 不会变。每条草稿：

- 每个字段都显示它依据的原文片段。引用不在原文里、引用太短不足以作为依据（`evidence.min_quote_chars`），或字段里的数字引用里没有（原文写 40%，字段写 60%）时，字段标**需核对**。这是代码核对，不再调用 AI。没有标记只表示找到了引用，不表示字段内容就对。
- **采用**按原样加入，得到新的 id 和来源（画像、自述、简历），绝不覆盖已有素材。**先修改**可以改完再**按我的修改采用**。**丢弃**不要这条。采用和丢弃也会把草稿文字从数据库里清除。
- 上面的素材库有未保存的改动时不能采用：采用会重新载入表单，改动就丢了。素材库在别处改过时，采用会被拒绝，页面重新载入。

草稿 `import.draft_ttl_days` 天后删除，无论是否审核过。同一时间只运行一次提取。再次提取同样的文字，会替换这段文字还在等待审核的草稿。ai-worker 重启后，提取不会重跑：它失败、文字被清除，需要你重新发送。

## 写申请回答（`/jobs/<id>/apply`）

职位页上的**写申请回答**打开这个职位的工作台（按钮上显示有定稿的问题数，例如 `1/3`）。手机上同一个入口是职位页底部栏里的笔形按钮。`writer.yaml: enabled` 为
`false` 时，按钮通向 设置 → 工作流，工作台只说明怎么开启；之前保存的回答仍显示。

工作台分三栏（窄于 1024 px 时一次一栏，在顶部切换）：

1. **素材**：当前问题的素材。每次勾选都立即存到问题上；按**生成**之前什么都不发送。
   - **JD 要点**，来自职位的拆解（[breakdown.zh.md](breakdown.zh.md)），分为必须、加分和其他；新问题默认勾选全部必须项。
     没有拆解时这一栏提供拆解按钮（拆解功能关闭时只作说明），也可以改勾**同时发送一段 JD 原文**（去除 AI 陷阱之后的
     JD，按 `jd_max_chars` 截断）。职位没有 JD 时也会说明。拆解或素材改了、勾选的某项已不存在时，这一栏会提示，**移除**即可去掉；失效项不会发送。
   - **画像**：`me.yaml` 的简介、技能（含年限）和语言。不含姓名、联系方式、所在城市和签证状态。
   - **经历素材**：素材库里的条目；新问题默认勾选技能与职位重合最多的 `stories.preselect_count` 条。
   - **这次想强调的**：一段自由说明，最长 `emphasis_max_chars`。
2. **问题**：粘贴申请表里的问题，或添加一封动机信（按一道长题处理）。每题有自己的原文、语气、目标长度（词数或字数）和回答语言
   （默认跟 JD 的语言，不知道时用 `language.yaml` 的 AI 输出语言）。每个职位最多 `questions.max_per_job` 题；删除问题会连同它的版本一起删除。
3. **回答**：按钮上方的框列出将要发送的全部内容和接收的服务商（`ai.yaml` 里 `write` 任务的顺序）。**生成**一次要 2–3 个不同风格的版本
   （`variants`）；和其他 AI 按钮一样在 Mac 上的 ai-worker 里运行，页面会等它完成。每次生成都新增版本；一题超过
   `questions.max_versions_per_question` 个版本时最旧的被删除（定稿版本始终保留）。

### 每句话的依据

AI 必须为每句话给出依据：JD、画像、指明的某条经历素材、你的强调说明或你的草稿里的一段引用。Job Radar 随后在代码里逐句核对，不再调用 AI：

| 标记 | 含义 |
|---|---|
| 有依据（无下划线） | 句子里的数字和名称都在引用里，引用也都在素材里找到了。 |
| 部分有依据（琥珀色） | 找到了依据，但句子里的某个数字或名称不在依据里；详情会列出。 |
| 无依据（红色） | 在这句话可依据的素材里找不到引用（关于你的句子不能只依据 JD）。 |
| 衔接句（点线） | 不含事实的衔接句。 |
| 你写的（灰色） | 你写的或改过的句子，不核对。 |
| AI 建议，未核实（琥珀色，点线） | 教练的建议，没有给出能找到的引用。 |

点一句话可看它的引用、各在哪里找到、缺了什么。说“我”“我的”的句子不管 AI 怎么标，都按关于你的句子核对。关于你的句子，数字和名称必须出现在它的有效引用里：只在 JD 或公司信息里出现的名称，不能支撑关于你的说法。关于职位或公司的句子还可以依据这两份文本。短于 `evidence.min_quote_chars` 的引用只有恰好是已知名称（比如“Go”）时才算。找不到的名称会标为**需核对**——
这是提醒你去看，不是保证：核对只认得像名称的词（引号里的词、带数字或中间大写的词、句中大写的词；见 `evidence.names`），
所以可能漏掉，也可能标出无害的词。数字按阿拉伯数字比较（“40 %”“40 Prozent”和“40%”算同一个数，“€85k”和“85,000 €”算同一个金额；紧挨着汉字的数字，如“下降了40%”，也算；全角数字按半角读；“5万”是 50,000、“3千”是 3000，但“500万”不等于 500，“40倍”不等于 40%）；用文字写的数字（“forty percent”）认不出来。**“有依据”只表示引用找到了，不等于句子属实。** 发送前请逐句读一遍。

**复制**复制纯文本。**修改**把你的改动另存为新版本：没改的句子保留核对结果，改过的标为“你写的”。**设为定稿**标出你实际发送的版本；职位页统计的是定稿数。

### 优化我自己的稿

按钮下面的**优化我自己的稿**接受你自己写的文字（任何语言），按这道题的回答语言、长度和语气写出一个新版本。两个选项：

- **贴合岗位**：保留稿里的事实，按问题和岗位调整。如果你勾选的画像、经历素材或强调说明里有能支撑你观点的事实，可以补进来，
  但不会凭空加。
- **只改语言**：只翻译和润色措辞，不增、不删、不改任何事实，也不会发送你勾选的素材，只发问题及其设置、职位名称和公司、
  你的文字。

框里会列出所选选项要发送的内容。你的稿就是它所说内容的依据：结果里的每句话都像初稿一样核对，“你的稿”是来源之一，所以来自你稿子的
事实会显示为有依据，你用另一种语言写也一样（引用原样摘自你的稿，数字按数值比较）。AI 加进来的、既不在你的稿也不在素材里的名称或数字，
照常标出。结果是列表里的一个新版本（“优化稿”或“只改语言”）；你的文字只留在这次请求里，请求结束时和其他请求一样清除。文字最长
`draft_max_chars`。

### 教练审阅

版本下面的**审阅**请 AI 像教练一样，对照问题和岗位读这一版。结果存在这个版本上，显示在它下面：

- **分数**，0 到 100，标明是 AI 的判断：这是意见，不是测量值，同一段文字两次审阅也可能不同；
- **各维度的结论**（不错、可改进、缺失）加一句说明，维度取自 `coach.dimensions`（默认：回答了问题、有具体依据、针对这家公司、覆盖必备要求、
  长度、语言和语气、没有夸大）。AI 评了未配置的维度时，这一项被略去并计数；
- **逐句建议**：哪一句、哪里不好、更好的句子。建议的句子和其他句子一样，对照你的稿和勾选的素材做依据核对。如果它没有给出能找到的引用，
  就显示为 **AI 建议，未核实**：它可能是对的，但目前没有依据，使用前请自己确认属实。指向这个版本里不存在的句子的建议被略去并计数。

**采用这句**另存一个新版本，其中那一句换成建议的句子（被审阅的版本不变，仍带着它的审阅）；采用的句子保留建议自己的核对结果。
**按这些建议改一版**请 AI 套用建议写出一个新版本，像初稿一样核对（“教练改写”）。**重新审阅**会替换已存的审阅。审阅会发送这个版本的文字
和勾选的素材，框里会列出。审阅和改写用的是 `write` 任务，和本页其他功能一样。一道题同一时间只跑一个请求：写、润色或审阅还在进行时（包括在另一个标签页或设备上发起的），再发起第二个会被拒绝，提示“已有请求在进行”，而不是悄悄丢掉。

审阅和改写里，作为引用来源的“你的稿”只包括这个版本中你自己写的句子，或本来就有依据的句子。AI 写的、没有依据的句子，不能靠引用自己来给自己（或给某条建议）做依据。

### 导出定稿回答

问题列表下面的**导出为 Markdown**会下载一个文件（`<公司>-<职位>-answers.md`），里面是每个有定稿版本的问题和它的定稿回答。文件由浏览器根据页面上已有的内容生成：
不会发给服务器或 AI 服务商，服务器上也不写文件，所以写作功能关闭时同样可用。没有定稿版本的问题不进文件；还没有定稿时按钮不可用。
你的文字里以 Markdown 符号开头的行（`#`、`-`、`>`、`1.`、`___`、代码围栏）、缩进四个空格以上的行和其中的 `<` 会被转义，保持为普通文字。没有问题文字的求职信会引用为“求职信”，而不是空引用。依据标记不进文件。

### 以以前的回答为底稿

输入问题时，Job Radar 会在**其他职位**有定稿回答的问题里找。有读起来相近的，表单就会提示（“你以前回答过类似的问题”），并写出是哪个职位、两个问题共有多少词。
点**以它为底稿**会添加新问题，并把以前的回答放进右侧的编辑框；在你按**存为第一个版本**之前什么都不保存（也可以**丢弃**）。

- 相似度是两个问题共有词的比例（忽略重音、大小写和标点，并去掉两家公司的名字和 `reuse.stopwords` 里几乎每个问题都有的词），至少 `reuse.min_similarity` 才提示；最多提示 `reuse.max_candidates` 条，最相似的在前。
  词按原样比较，所以**同一个问题换一种语言就匹配不上**。中文按单个汉字比较，所以一个很短的中文问题也算几个词。问题少于
  `reuse.min_question_words` 个词时不查找。
- 这只是起始文字，不是核对过的回答：以前的核对是针对另一个职位的素材做的，所以每一句都按“你写的”保存；**生成**仍然根据你选的素材起草。
- 文字里还有底稿来源那份回答的公司名时，编辑框里和保存后的版本下面都会出现提醒（刷新后依然在）。核对按整词查找公司名，也查找去掉法律形式后的名字（“Acme GmbH”也查“Acme”），
  所用的法律形式和流水线的公司匹配相同（`company.legal_suffixes` 和市场包）。读起来像普通词的公司名匹配得更严：三个字母以内只认和库里完全相同的写法，且不算句首的词（It）；更长的普通词只认首字母大写（Target）。提醒里写的是库里存的公司名。
  与那个职位相关的其他名字（产品、团队、人名）它认不出来，所以请通读一遍。
- 提醒是根据版本来源的那份以前的回答算出来的。那个版本被清理掉之后（超过 `max_versions_per_question` 的旧版本会被清理），
  由它起步的文字的提醒可能随之消失。
- 查找只读你自己的数据库，不调用 AI 服务商；只在写作功能开启时可用，是因为添加问题的表单属于写作功能。

### 发送什么，留下什么

只发送披露框里列出的内容，只在你按**生成**、**优化**或**审阅**时发送，只发给 `write` 任务的服务商。不联网搜索。请求把素材从数据库带到
ai-worker；请求完成、失败或过期后，素材从请求里清除，只留下问题 id 和素材的哈希。排队超过 `queue_timeout_seconds`，
或运行超过 `timeout_seconds` + `expiry_grace_seconds` 的请求算过期。生成的版本连同核对结果存在你自己的数据库里。

清除只作用于请求这一行：

- 请求未结束时做的备份会留下素材，包括部署时的迁移前备份。日备和周备约保留 8 周，系统备份和手动备份更久
  （[backup-restore.zh.md](backup-restore.zh.md)）。
- Postgres 的堆和 WAL 也可能留着，直到 vacuum 和 checkpoint。

### 从你自己的 AI 客户端写

你配置的 MCP 客户端可以读取一道题的材料并新增答案版本，用的是两个默认关闭的工具。它们只新增版本，这些版本在这里标为“来自你的 AI 客户端”，带各自的核对结果；它们读到的内容会发给该客户端的模型服务商。见[从客户端写答案](mcp.zh.md#从客户端写答案)。

## 设置（`writer.yaml`）

| 键 | 默认 | 含义 |
|---|---|---|
| `enabled` | `false` | AI 写作功能总开关。为 `false` 时，素材库的任何内容都不会发给 AI 服务商。也可在 设置 → 工作流 里改。 |
| `timeout_seconds` | `180` | 单个写作请求从 ai-worker 领取起的最长运行时间；超过时 AI 调用停止，请求以超时失败。也可在 设置 → 工作流 里改。 |
| `expiry_grace_seconds` | `60` | 运行中的请求超过 `timeout_seconds` 加这段余量还没结束（worker 退出或卡住），标为已过期，素材清除 |
| `queue_timeout_seconds` | `900` | 排队最长等待；超过的排队请求标为已过期，素材清除 |
| `stories.max_items` | `60` | 素材库最多几条 |
| `stories.title_max_chars` | `120` | 标题最长字符数；也是单条数字、技能、标签的上限 |
| `stories.text_max_chars` | `1500` | “做了什么”和“结果”的最长字符数 |
| `stories.preselect_count` | `4` | 新的申请问题默认勾选几条素材 |
| `import.max_file_bytes` | `2000000` | 简历文件最大字节数，更大的不读取直接拒绝 |
| `import.max_chars` | `30000` | 发给 AI 的原文最长字符数，更长的会截断 |
| `import.min_chars` | `20` | 文字比这更少时视为没有可提取的内容 |
| `import.formats` | `[pdf, md, txt]` | 简历可用的文件类型 |
| `import.max_drafts` | `12` | 一次提取最多返回几条草稿 |
| `import.pdf_timeout_seconds` | `15` | 读取一个 PDF 的最长时间，超时即停止并请你粘贴文字 |
| `import.pdf_max_memory_mb` | `256` | 读取一个 PDF 最多占用的内存（MB） |
| `import.draft_ttl_days` | `14` | 草稿等待审核的天数，过期删除，无论是否审核过 |
| `questions.max_per_job` | `12` | 每个职位最多几题 |
| `questions.text_max_chars` | `1000` | 问题原文最长字符数 |
