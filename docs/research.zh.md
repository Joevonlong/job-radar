# 公司背景

[English](research.md) | [中文](research.zh.md)

岗位页可以显示这家公司公开可查的信息：做什么、行业和规模、成立时间、总部、融资、产品、工作语言、员工评价网站怎么说、近期动态。这些内容在你按下按钮时，由 AI provider 通过网页搜索得到。**默认关闭。**

面板里的一切都是 AI 网页搜索的结果，面板上也这样标明（“AI 网页搜索 · 未核对”）。Job Radar 没有核对来源是否正确。要依赖某个字段，先看它的来源。评分、过滤、推送和其他 AI 任务都不用这些结果，它们只用来显示。

## 打开

设置 → 调研 →“启用调研”，或者在 `data/config/research.yaml` 里写 `enabled: true`。之后岗位页标题下方会出现调研条，“公司背景”面板里会出现“查公司背景”按钮。用出厂的 `research.yaml` 时，收藏岗位也会自动开始调研（见[自动调研](#自动调研)）；你保留的旧文件在你改之前一直是手动。

用哪个 AI，由 AI 页的任务“公司背景”决定。默认顺序是 `claude-cli`，然后是 Anthropic API。只使用能搜索网页的 provider。一个可用的都没有时，面板会说明，不显示按钮。

## 什么会离开本机

| 发送的内容 | 何时 |
|---|---|
| 公司名，已去掉标记和控制字符 | 每次查询 |
| 公司官网域名，**仅限你自己确认过的** | 这家公司的每次查询 |

绝不发送：岗位标题、地点、JD、你的画像，以及 Job Radar 从岗位推断出的域名。任何人都能在岗位里写任意链接，所以这种域名既不进入请求，也不进入 AI 可打开的网页列表。

这些内容发给该任务的 provider，由它去搜索网页。被读取的网站看到的是来自 provider 的请求，不是来自你的。

## 调研条

岗位标题下方有一行，说明这个岗位的公司查询、JD 拆解和查薪资各到了哪一步：结果多久以前的、进行中、被用量上限暂停（带恢复时间）、失败、未开启（带设置链接）或还没查。每一项有自己的按钮可以重新运行；“全部调研”运行所有没有最新结果的项。这些都算手动：用手动上限，排在自动请求之前；按下时，同类正在等待的自动请求也会提到前面。调研关闭时，调研条只列出已存的结果，没有按钮；没有任何结果就没有调研条。

## 公司列表

在 `/companies`，有已存结果的公司用一行显示摘要和规模。“详情”打开同样的字段和来源，只读，标为未核对；还有一个重新查询的按钮（算一次手动查询，通过这家公司最新的岗位发起），以及确认或修改官网。打开列表不会发送任何东西：没有结果的公司还是没有结果，也没有“全部查询”的按钮。

## 自动调研

`enabled: true` 并设置 `auto.trigger`：

| `auto.trigger` | 什么时候开始 |
|---|---|
| `manual` | 不会自己开始 |
| `favorite`（出厂值） | 你收藏岗位时，网页或 Telegram 都算 |
| `favorite_or_applying` | 另外，岗位状态变成感兴趣、准备中或已投递时 |

`auto.items` 决定运行哪些（`company`、`breakdown`、`salary`）。薪资还需要 `salary.yaml` 的 `lookup.enabled`，拆解还需要 `breakdown.yaml` 的 `enabled`；关着的项会跳过。

**发送什么：** 公司查询发送上面列出的内容。自动查薪资发送公司名、岗位标题、城市、国家和资历（见[查薪资](salary.zh.md#查薪资ai-加网页搜索)）。拆解照常把 JD 发给该任务的 provider。**这些请求的时间反映出你收藏和投递了什么**，手动按按钮时不会以同样的方式透露。如果你在意这一点，保持 `auto.trigger: manual`。

**上限：** `auto.max_per_day` 是收藏和投递岗位每 24 小时的运行次数，按岗位计数，和手动上限分开。全部命中缓存的运行不算；同一岗位 24 小时内最多算一次，不管是什么触发的。超过上限就不排队，活动日志会说明。

**用量上限：** 如果 provider 冷却、用量上限或 API 预算此刻会挡住联网查询，就根本不排队，之后可以在调研条上自己发起；拆解仍然排队。这些检查只读共享状态，所以收藏不会启动 provider，也不会移动窗口。

**撤销：** 取消收藏或撤销状态不会取消已经排队的请求，只是不再发起新的。

**关闭：** `auto.trigger: manual` 停止新的运行。`enabled: false` 还会让 ai-worker 停掉队列里剩下的自动请求；你自己发起的查薪资和拆解不受影响。

### 高分新岗位

`auto.high_score` 默认关闭。打开后，每轮的后段 AI 步骤会为新岗位排队调研：`max_age_days` 天内首次出现、分数至少 `min_rank`、未关闭、没收藏过也没调研过。每轮最多 `per_cycle_limit` 个，每 24 小时最多 `high_score.max_per_day` 个，和收藏岗位分开计数。这会为你还没看过的岗位发送同样的内容，用量也更多。

## 公司官网

面板会问你这家公司的官网，因为确认过的域名能帮搜索找对公司：

- **待确认的建议。** Job Radar 取这家公司岗位链接里最常见的域名（`careers.example.de` 变成 `example.de`），跳过招聘平台和 ATS 主机（`company.non_company_hosts`）。建议只是存下来并显示：按“确认”之前，它不会被发送，它的网页也不会被打开。
- **你自己填的。** “修改”或“填写官网”接受域名或粘贴的网址。服务端把它缩减成域名，并拒绝 IP 地址、本地名称、公共后缀和招聘平台。

你填写的域名不会被建议覆盖。

## 限制能管到哪里

- **`claude-cli`**：只对 `company.allowed_domains` 里的站点和你确认的域名预先放行打开网页，其他工具调用一律拒绝。这是 CLI 自己的权限检查，不是网络边界。它的网页搜索**不受**这些站点限制。
- **Anthropic API**：搜索结果和打开的网页由 API 限制在这些站点内，`max_searches` 也由 API 执行。
- **`codex-cli`**：不在默认顺序里，因为它的网页搜索完全不限域名。如果你自己把它加进这个任务，面板和设置的 AI 标签页都会提示。
- 站点列表里如果有私有地址、本地名称或公共后缀，加载文件时会被拒绝。

## 存储前的检查

回答不可信：AI 读过网页。每个字段独立判断。出现下面任何一种情况，这个字段就被丢弃，并计入面板上的丢弃数：

- 来源不是公开的 `https` 链接（不能是 IP 地址、本地或保留名称，不能带账号密码或其他端口）；
- 文字或来源链接里有不可见字符；
- 文字或来源链接里有写给 AI 的内容（用 `traps.yaml` 的指令模式判断，不管岗位陷阱扫描是否打开）；
- 数值不可能成立：员工数或评分超出 `company.employees` / `company.rating`，成立年份或新闻日期在未来，或日期格式不对。

剩下的内容是纯文本，长度受 `company.max_field_chars` 限制，显示时也是纯文本，来源是链接。一个字段都不剩时，不保存任何内容，面板说明没有可用结果。`traps.yaml` 读不出来时，查询直接失败，不保存未经检查的回答。

## 结果

结果属于公司，所以这家公司的所有岗位都显示它。它在 `company.ttl_days` 天内算有效。过期后面板仍然显示，并提示可能过时。“重新查询”总是重新搜索。确认了另一个官网后，已存结果就不再算有效，面板会提示。两家公司合并时，结果移到保留的公司。

关闭功能后，结果仍留在数据库（表 `company_research`），面板继续显示，只是没有按钮。删除数据库才会删除它。

## 上限和费用

- `company.max_per_day`：过去 24 小时的请求数。每次请求都算，失败的也算；直接用已存结果的不算。
- `company.max_searches`：一次查询的搜索次数。Anthropic API 严格执行，CLI 只是被要求遵守。
- `company.timeout_seconds`：整个查询的时间，包括所有 provider 和重试。
- 查询会消耗 token；用 Anthropic API 时每次搜索还有费用（用量页按 `company.web_search_usd` 计算）。见 [ai-usage.zh.md](ai-usage.zh.md)。

## `research.yaml`

表单包含开关、`ttl_days`、`max_per_day`、`max_searches` 和 `timeout_seconds`。其余的键在文件里改；`company.allowed_domains` 和 `company.non_company_hosts` 决定本机可以抓哪些主机，所以网页端（包括高级编辑器）不能修改，只能手动改文件：

| 键 | 作用 |
|---|---|
| `company.allowed_domains` | 除你确认的域名外，可以打开网页的站点。不能是私有或本地名称，也不能是公共后缀。 |
| `company.non_company_hosts` | 绝不当作公司官网的主机（招聘网站、社交网络）。 |
| `company.max_field_chars` | 一个字段最多存多少字符。 |
| `company.employees`、`company.rating` | 这些数值的合理范围。 |
| `company.web_search_usd` | 用量统计里一次搜索的费用。 |
| `auto` | [自动调研](#自动调研)。没有这一块的 `research.yaml` 按 `trigger: manual` 处理。 |

## 回滚前

迁移只新增一张表和 `companies` 的三列，旧代码会忽略它们。旧代码也会忽略 `research.yaml`。如果表单保存时把 `tasks.company_research` 写进了 `ai.yaml`，旧代码会拒绝这个文件：切换前删掉这个键（以及 `reasoning_effort_by_task.company_research`，如果有）。

自动请求带一个旧代码不接受的标记。退回到没有调研条的版本前，把 `enabled` 设为 `false`，等队列里没有 `origin: auto` 的请求；留下的请求会以无效请求失败，不影响别的。这个功能之前的版本不接受 `research.yaml` 的 `auto` 块：也要删掉。`research_auto_runs` 表保留，旧代码会忽略。

## 出问题时

| 面板显示 | 怎么办 |
|---|---|
| 没有能搜索网页的 provider | 在 AI 页给这个任务选 `claude-cli` 或 Anthropic API |
| 登录或密钥被拒绝 | 修复 CLI 登录，或 `.env` 里的密钥 |
| 达到每日上限 | 等一等，或调高 `company.max_per_day` |
| 没有内容通过检查 | 没有保存任何内容。稍后再试；名字对应多家公司时常常查不出结果 |
| `research.yaml` 读不出来 | 运行 `pnpm config:check` 查看原因 |
